# 原 Android 宿主交接：采用范围

本轮关闭 API 35 Xiaomi 原宿主的小夹具呈现/释放前置缺口，尚未接入密集 S2。验收和机器可读证据见 [verification.json](verification.json)，源输入、失败记录、测试 XML、仪器输出及普通进程合成笔记在 [evidence.zip](evidence.zip)。原有用户笔记内容不进入归档。

原 1024×768 上传只预留 4096 字节行宽，设备返回 5120，导致完整 Path 持续回退。现每行额外预留一个 4096 字节块，仍受原 pool/executor 总预算和实际副本校验约束。此预留是有界候选，不是所有厂商的 stride 上限，也不扩大总额度。接近额度的视口可能更早回退，回退占比及成本仍需后续测量。

上传修复后，原跨 SurfaceControl/窗口的半透明动态叠加为 `ff6aa080`，提交后稳定为 `ff3f9f5f`。采用半透明活动输入期间的完整 Path 同 Canvas 合成；原静态源沿既有 on-draw 移除和真实回执退役，输入继续持有，抬笔后恢复原生静态帧。真机复验两端均为 `ff3f9f5f`。没有归因到具体厂商色彩算法；密集页回退成本仍待测。

原仪器流程在 1024×768（重建/替换同范围）通过动态覆盖、翻页/缩放/尺寸变化、已接受保存及新 owner 重开、端点丢失、迟到 worker、实际 callback/fence、确认丢失与只读对账、owner 退休。2880×1800 超限全屏确认完整 Path 可见且没有原生发布。初始 18,874,368 字节为资源声明扣账，不是物理 heap 峰值。长时间未信号 GPU fence、恢复 pending 载荷与 Apple 本轮未测。

同一最终调试 APK 的普通进程另以 ADB 模拟手指创建高亮合成笔记，完成撤销/重做、两页三笔、确认保存、强停后新 PID 重开，文件逐字节保持；之前两份笔记摘要不变。不是主动笔或延迟/帧门槛验收。新预览包 SHA-256 为 `ce77e409a13065ad0c532c46b224b5bb0a2563028f1c6fe2053e3a783244cd93`。

下一步按现行计划处理 S2 10,000 笔/100 万点与默认 5,000 对象/8 MiB live 额度的准入差距，再把分批完整输出接到同一呈现与退休链。不要通过提高常量、换小样本或累计历史测试数宣布 S2/C1 完成。
