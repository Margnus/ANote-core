# LIB-07 批量组织业务规则

## 交付卡

起点Core fc4f78d。现行计划允许隔离业务规则；LIB-06/DATA-04验收依赖及M-1/C1/DEV-041门禁不改。目标：批量移动、收藏、入回收站在同一完整空间/版本上生成完整计划，任一失效身份或坏快照整批拒绝，不能返回部分成功。本轮不接生产/App；复制继续复用PagedPreviewCodec.copyAsNew，不建立另一内容模型，整项仍待验收。

验收：空选择、重复选择、超过1000候选、未知身份、旧版本/跨空间/不完整/坏引用拒绝；成功逐项语义与既有单笔规则相同，选中noteId不变、顺序按请求保留、非选中内容不变；一次批次只执行一种操作，同目录/同收藏值可产生无变化行。共享测试覆盖三个操作、坏项在末尾、输入保持及并发版本失效。

## 事务与接入出口

本规则复用文件夹、视图、回收站既有快照校验，各操作只读取本操作所需的完整元数据。验证一次后按ID索引生成全部before/after，避免每条重新扫描全量快照。1000是候选选择准入，不是生产性能/heap承诺。快照和请求列表须由同一owner在调用期间保持稳定；输出列表为新集合，不持有输入选择。

计划不是提交：未来唯一事务须核对外层space/revision以及每行before，原子应用整批并推进一次元数据revision，失败整批rollback，opId回执保证重试，不可循环逐条提交。移动不改正文保存目标/内容版本；收藏不改正文更新时间；回收站只移除活动位置并添加同noteId历史位置，无正文/资源删除。生产需整合统一元数据schema和owner，不能将这些规则快照变成多个authority。

采用后仍需实际事务/失败注入、双端批量选择/结果UI、编辑中移动与回收协调、保存重开、资源保护与复制的完整App引用映射。既有copyAsNew仅覆盖当前预览页/层/笔迹，不等于未来全部图文/PDF对象、资源引用与历史已复制。不得用已有复制函数将LIB-07整项标验收。

## 实际结论

采用为未来唯一元数据事务的批量组织规则。新增9项共同测试通过，原单笔目录/视图/回收站回归保持，共492项JVM XML零失败，shared本轮执行、canvas复用；[绑定报告](../reports/library-batch-rules.json)。可移植性/架构检查通过。无平台App改动，不重建未变化APK；不声明实际事务原子性、双端UI、耐久保存或完整复制已验。
