# 资料库元数据分页查询候选

2026-10-29，LIB-09/LIB-05的生产接入前查询决策。依据现行开发计划允许的C–F独立存储调查；本候选不连接App数据库、不冻结生产DDL、不解除M-1/C1/DEV-041门禁。

现有`LibraryViewRules`针对完整有界快照排序，不能承担一万条元数据按页读取。候选在唯一临时SQLite库中放入10002条主空间合成元数据（另有跨空间样本），正文与图片置于独立表。查询只读取元数据覆盖索引，按页返回最多`limit`行并用额外一行判断是否有下一页；不先载入整个目录再切片。完整内存oracle只在外部验证驱动中生成，不是查询实现。

## 采用的查询约束

- 游标绑定空间、排序、收藏过滤、空间元数据版本和最后一条的完整排序键/身份。继续查询前在同一短读事务内核对版本及原anchor行；跨查询、伪造键/缺失anchor、旧版本明确拒绝。无效游标不返回部分新结果，调用者须重新查询。
- 标题顺序沿用原Kotlin UTF-16代码单元顺序，候选使用UTF-16大端BLOB键；身份用同样编码打破相同主键。原始标题不改大小写、不规范化、不按拼音或自然数排序。真实反例中SQLite默认BINARY为`U+E000 → 😀`，Kotlin为`😀 → U+E000`，因此否决默认文本排序可直接等价替代的假设。
- 更新时间/最近打开倒序以`Long.MAX_VALUE - time`的固定八字节大端键表达，再以身份升序。覆盖0/Long.MAX_VALUE与相同时间；最近列表排除未成功打开的记录。回收站默认排除，空间与收藏过滤先进入索引前缀。
- 每页自己的短事务先读版本、再读当前页，结束后释放读快照。页内并发修改仍返回完整旧快照；下一事务发现版本变化便拒绝旧游标。不会保持贯穿整个滚动过程的长事务，也不尝试把新旧页拼成完整结果。
- 合成schema的insert/update/delete触发器推进原空间版本；版本必须保持非负SQLite INTEGER，耗尽导致整条修改回滚，不能溢出为REAL。该版本列和触发器仅属于隔离schema，不是新建App元数据authority。生产实现仍须由原单写者在同一事务内发布元数据、派生排序键及受检版本。

## 实际结果与范围

[报告](../reports/library-paging.json)及[查询实现](../tools/library_paging_probe.py)、[验证驱动](../tools/verify_library_paging.py)可复跑。6种NAME/UPDATED/RECENT与收藏组合共938页，页长37，分别返回9092/3032、9092/3032、7793/2599条，均与独立代码单元/数值比较oracle完全一致，身份无重漏。计划全部使用覆盖索引，无临时排序；keyset单页最多1213 VM步骤，同源UPDATED第8000条OFFSET见证为24402步，对应keyset最多921步。VM步骤只说明该候选查询工作，不证明延迟、heap或手机/平板性能。

SQLite authorizer先实际证明正文/图片读取被拒绝，再在全部分页中只允许观察到fixture标识、空间版本及元数据三张表读取。双连接WAL在读版本后修改一条元数据，当前页保持原版本精确内容，后续旧游标拒绝；插入/删除同样拒绝，重查完整新结果一致。空空间、跨空间、页长非法、伪造排序键/身份以及版本耗尽回滚已验证。源库仅在build唯一临时目录中生成并关闭清理，现有双端笔记/安装包未操作。

采用上述keyset/完整排序键/短事务版本围栏作为查询候选，停止同类主机正样例扩展。尚未实现生产迁移/DDL、平台SQLite绑定、万条普通App列表、异步封面/取消、滚动锚点重定位或耐久偏好。粗粒度空间版本在无关元数据更新时也会使游标失效，UI须明确重查并通过稳定noteId恢复位置；不能无限自动重试或声称不断编辑时始终遍历成功。派生排序键的写入一致性、生产索引大小/写放大、正文变更如何推进目录版本，以及目标设备性能均待原生产事务与设备验收。LIB-09仍部分实现/待验收，完整C1与生产SQLite不放行。
