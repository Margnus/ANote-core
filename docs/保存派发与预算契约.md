## 会话接管验证与pending恢复的前置边界

原PagedPreviewNotebook.open仅消费已有不可变root、已验证DocumentBudget值与原owner检查；它不读写文件、不隐藏第二个authority。失败结果不含notebook；nonce/预览范围、原reader能力、原authority初始page/object/live/identity额度分别返回明确原因，成功保留原root身份且只建立原会话。原constructor仍保留兼容前置条件，owner检查/分配/程序错误不被catch伪装为内容拒绝。原Android/Swift adopt已接此入口，不能据此宣称全部公开API或持久恢复完成。

pending持久恢复尚未接入，接续必须满足：

- 已提交root与精确pending命令（page、operation/object身份、base revision、原笔刷及全部真实点）属于同一份有界恢复责任；不能把root.capture成功当pending已保存。
- 当前pending不推进root revision；原ledger同版本不同正文必须继续拒绝分叉。若允许恢复checkpoint扩展，须定义严格扩展关系、flight与latest分别计费以及旧回执不得释放/确认新恢复内容；不能只改version或伪增root revision。
- 原worker真实写入确认后才可报告恢复记录保存；重开须先有界验证完整恢复输入，再在唯一owner上重试原命令。坏/截断/不支持/同版本分叉须保留原件且明确拒绝，不能只加载base并静默丢pending。
- 必须在原ledger/IO/两端消费者覆盖老root写入在途、checkpoint失败重试、断点重开与成功提交后清除恢复责任；格式选择、原文件兼容和崩溃窗口须一并说明。当前没有新增格式/旁路存储，也不把本节设计当持久恢复实现或SQLite门禁通过。

## 2026-10-23 Android原Store显式永久退休

Android在原NoteStore/main Handler/BoundedOwnerExecutor/ledger及同一render pool内增加beginOwnerRetirement。普通releaseActive仍只返回资料库、保持App级worker可复用。永久退休在原主owner请求，不能把STARTED当作写入所有权已转移；只有RETIRED/onRetired后才可按原文件建立下一可写owner。本接口不提供全局跨Store租约或跨线程接管。

| 结果 | 状态与责任 |
|---|---|
| INPUT_PENDING | 活动笔或完成pending存在，原样拒绝，不取消/丢样本 |
| TRANSFER_PENDING | 外部picker仍持有原快照，匹配完成/取消交接前不退休 |
| WORK_PENDING | 原读取/导入/导出请求在途，或当前结果仍DELIVERING/DELIVERY_BLOCKED；交付返回后重试，防止退休后重新adopt |
| SAVE_REJECTED | 当前根未获原ledger准入，保留当前会话和已有失败快照 |
| STARTED / ALREADY_RETIRING | 停止新会话/新请求/新picker准入，当前根交原保存泵；同一owner继续ACK和真实回执，重复请求不替换观察者 |
| RETIRED | 原ledger为空、native image/render责任drained、原worker entries已ACK并实际停止后才取出/清空完成接收者；通知异常不反转退休或重跑IO |

一般请求只增减有界计数，不另存payload/第二队列；请求交付内的退休请求和保留写重试在任何状态变更前拒绝。private请求入口在退休后拒绝新IO，原draw也不能再创建pool；原native只读协调先检查drain外条件。首次永久退出使用closeWithoutView，不能依赖已退出View的下一次draw；已排draw移除后再失去端点的处理见下节，不把移除提交当作资源释放证明。

### 已确认排draw移除后的端点消失

`applyTransactionOnDraw`只合并到下一次draw，不主动调度draw，见[Android原契约](https://developer.android.com/reference/android/view/AttachedSurfaceControl#applyTransactionOnDraw(android.view.SurfaceControl.Transaction))。因此首次普通close确认排队后，原SurfaceImage保留同一child引用与一个布尔责任，但立即清除旧ViewRoot引用；原Store即使已inkRetiring，进度入口仍须识别弱呈现端消失。

只有已确认排draw且没有handoff/cleanup歧义的移除，才允许一次直接补交同一child的空buffer/隐藏事务。补交前清除可补交标记；成功、失败或child已无效都不循环补交。原待draw事务后续仍只能移除，不重新提交原buffer。不重建pool、不重复关闭ImageReader/HardwareBuffer，不用超时释放；原callback及有效fence完成后才能结算charge。空buffer释放原显示buffer及release callback/fence含义见[SurfaceControl原契约](https://developer.android.com/reference/android/view/SurfaceControl.Transaction)。歧义原调用不属于这个可补交范围，继续保留责任。

验证使用原App层级：先有实际compositor像素，再通过OnPreDrawListener阻断后续draw，保持Surface/层级存活；先普通detach排移除，再断开消费者链接/清弱端点并请求同一worker保存。检查真实回执/fence已到而软件结算门禁仍保charge，允许结算后旧pool归零，移除监听并在原Store重新呈现。该受控端点丢失不是GC时序、突然owner线程消失或普通UI验收。

retryRetainedWrites在原活动/退休owner重新offer失败快照，保存按钮接显式重试后再按原保存入口处理当前根；返回true不是耐久确认。后端已停或结果交付中拒绝重试，内容仍由原ledger持有。实际IO失败、长期未返回回执或UNKNOWN不能当已退休；调用者须保留恢复入口，不因超时/GC释放或重复破坏性清理。

验证分为六项真实原Store/worker文件检查与三项原层级native检查：原根IO完成与worker停止、失败后修复重试、活动笔/picker拒绝、读取与结果交付门禁、满8文档后第9本恢复、错误线程拒绝；实际release/fence前保留原责任、迟到CPU ACK及排队保存、UNKNOWN只读协调后再停止。测试只写唯一cache目录，原笔记哈希另核；不以JVM GC时间、软件结算延迟代替真实长期未signal fence，也不证明突然owner/线程丢失、进程死亡或整体heap。

| disposition | attempt/状态变化 | 宿主责任 |
|---|---|---|
| READY | 唯一attempt，分配序号并标该文档flight | 原worker准入；拒绝必须退还，完成按原attempt结算 |

| BACKPRESSURE | 无新attempt，不消耗序号，不修改flight/latest | 等既有worker进展再pump，内容仍由ledger持有 |
