# 预览保存派发与预算契约

## 2026-10-23旧root与导出持有修复

本轮沿上述责任清点修复原路径，不增加调度/内容authority：

- notebook projection在成功commit、合法切页及retire时立即清空，不等下一次draw；拒绝的编辑保持当前projection。退休会话仍可只读查询，但不重新建立常驻projection。这只移除该缓存的引用，不代表history/journal/原生cache中的样本或系统heap已经释放。
- Android activeSavedRoot与Swift savedRoot改为当前会话的savedVersion标量。采用依据是同一原authority内root revision严格递增、undo/redo也生成新revision；adopt和关闭必须重置标记。真实保存完成只有在其捕获root与当前root身份相同时才能更新，旧flight不为较新内容背书。Android对外save的跳过IO还要求传入root就是当前notebook root，不能把其他同版本内容认作已保存。它是原预览的IO优化标记，不是新的durable receipt或跨会话幂等权威。
- Android原exportSnapshot明确为单个待选择器结果的持有槽：beginExport已有内容时拒绝覆盖，takeExportSnapshot将引用交给完成/取消处理并清空该槽；Activity缺少选择器也走同一清理。exportRetainedByteCharge报告该槽快照的原codec保留额度，单份不超过8MiB。选中目标后仍由原worker以encodingWorkByteCharge准入；取消时归零仅表示此槽不再负责，不能当作物理内存归零。
- Apple原transferBusy/exportDocument保护继续只允许一个导出准备和一份结果。worker运行时持有捕获root，ACK后仅原PreviewBackup Data由UI持有到完成/取消；重复prepareExport不覆盖首次结果。16,000,000 UTF-16单位的编码界限给出UTF-8数据不超过48,000,000字节的保守上界，FileDocument/平台隐藏副本仍须计入后续物理测量；未把Data或选择器当另一份正文authority。

验证出口：JVM检查真实projection引用而非GC时长；Android真实原store/worker在唯一cache目录验证无编辑跳过IO、编辑后失败保留、修复后原root重试、重开标记、相同revision的外来root不误报保存及导出槽准入/交接。Swift真实宿主验证无编辑保存/编辑失败恢复和两次导出交接。具体执行结果见当前状态与对应报告；均不证明系统文件选择器UI、断电、真机heap或完整总预算。

仍需收敛：输入producer/跨语言临时副本、pending元数据、history/journal/identity的提前准入与跨任务重叠，View/Path缓存及平台隐藏分配；原savedVersion不能解决任何这些预算。C1仍须完整证据与M-1。

## 唯一责任链

原notebook捕获不可变PagedPreviewSnapshot，原PreviewSaveLedger持有最新快照及每个文档唯一旧flight；原BoundedOwnerExecutor/AppleBoundedOwnerExecutor执行编码/平台IO。派发不新建队列、worker或内容authority。ledger的32MiB快照额度与worker的256MiB声明工作额度分别保留；旧flight与较新latest同时计费，不能用较新root替代正在执行的旧输入。

Android NoteStore与Swift PreviewModel在同一owner读取原worker状态，调用admitNextWrite(availableWorkBytes, maximumWorkBytes, backendAccepting)，READY后再调用原executor.submit。worker槽位/停止等第二道拒绝仍须returnUnstarted；此时没有执行IO，不记磁盘失败或已保存。接受的任务及返回结果直到真实matching completion/ACK之前保持原责任。

## 派发结果

| disposition | attempt/状态变化 | 宿主责任 |
|---|---|---|
| READY | 唯一attempt，分配序号并标该文档flight | 原worker准入；拒绝必须退还，完成按原attempt结算 |
| IDLE | 无新attempt；可能仍有flight或需显式重试的失败内容 | 不能当作已保存或全部drained |
| BACKPRESSURE | 无新attempt，不消耗序号，不修改flight/latest | 等既有worker进展再pump，内容仍由ledger持有 |
| WORK_CAPACITY | 当前可派发文档都超过单任务最大额度；无attempt | 明确容量错误并保留内容，不伪装等待后会自行恢复 |
| BACKEND_UNAVAILABLE | 有待派发内容但worker不再接受；无attempt | 明确后端不可用，不能误报为暂时字节背压；已在途IO仍可正常完成 |
| INVALID_BUDGET | 负available、非正maximum或available大于maximum；无attempt | 明确配置/输入失败并保留内容，不隐藏为成功 |
| IDENTITY_EXHAUSTED | 不再分配attempt，所有快照保留 | 明确后端身份耗尽，不抛出跨语言未声明的check异常 |

只跳过永久超过maximum的文档，让其他可执行文档继续保存；暂时超出available但可放入maximum的首个文档保留顺序，避免持续小保存让它饿死。同文档永远只一个flight，新的完整root留在latest，旧completion不能清空它。跨文档不是文档命令的全局提交顺序。

失败/未知IO保持快照并要求显式offer重试；较新完整快照仍可替换未开始/失败旧内容。重送不重跑已确认成功的旧attempt；returnUnstarted和complete都要求ledger身份与当前flight对象完全匹配，旧/外来attempt返回false。派发READY或Boolean保存入口受理不产生durable回执，App保存成功仍来自实际平台IO完成。

## owner与公开边界

ledger构造、查询及所有状态修改都先调用ownerCheck。Android绑定原executor.checkOwnerThread；Swift绑定原主线程检查。owner/程序回调异常原样传播，不转为容量失败。兼容构造默认空检查与nextWrite()只为既有可信调用方保留，不构成线程安全保证；实际双端App使用typed入口及显式owner检查。

本次没有冻结公共SDK、隐藏所有内部导出或提供任意不可信root factory。Snapshot为既有closed不可变类型，编码工作量由原codec计算；available/maximum是原worker同owner的即时观察，不是跨线程reservation。原executor仍是实际任务/额度准入权威。

## 验证与未决

公共回归覆盖预算坏值、暂时背压、超大文档与后续文档、排队顺序、旧flight/新latest、失败重试及owner异常；JVM用真实有界worker验证饱和后编码到临时文件并重开、槽位拒绝后退还、停止及外线程误用，临时文件往返不当作平台durability。另以反射到达Long.MAX_VALUE生命周期边界，仅为JVM反例，不在生产暴露测试修改口。

Android当前原保存端口通过原App SurfaceControl宿主中的保存/关闭/新owner重开回归；另用同一真实worker先阻塞渲染、排入保存A、停止接收后提交B，验证A不收到提前失败且只成功写入/回调一次、B未写文件并仍由账本持有。全局派发失败只通知未flight且无需显式重试的待派发内容，不把已接收IO当作失败；该证据与普通UI、真实触笔和heap分开。Swift接线源码需要实际Mac重新构建/运行36项宿主，Windows不宣称通过。当前结果见[保存派发报告](../reports/preview-save-dispatch.json)。
