# LIB-04/05 资料库视图业务规则

## 交付卡

起点：Core cb96f25；现行计划允许不接生产的独立业务规则。目标：最近按打开时间排列、收藏可取消、名称/更新时间切换排序时同值顺序确定，刷新按noteId保持定位；列表/网格偏好作为显式元数据。范围为shared-core internal纯规则，不新建authority、IO或公开SDK，不改普通App。

验收：同空间/同revision完整快照且ID唯一、Unicode/时间有效；最近排除未打开项，时间降序；名称保持原文档120 UTF-16单元/合法Unicode契约（含旧空标题，不在视图层偷偷重命名），按原UTF-16序升序、更新时间降序，同值均用noteId升序打破平局，不依赖输入枚举顺序。收藏视图只过滤收藏项。原锚点存在则保持noteId及行内偏移；消失则选择旧索引处最近可用行并清零偏移，空列表无锚点。收藏/成功打开记录/偏好只返回版本绑定before/after，拒绝保持原件。名称规则是确定性候选，不声称本地化拼音/自然排序。

依赖与出口：LIB-01、DATA-01/DEV-041和M-1/C1不变。采用为未来同一元数据事务及两端列表消费者规则；完整排序只能用于明确完整且有界的快照，不能用于万条数据库分页或宣称LIB-09性能达标。生产应由索引查询执行相同排序键，并在实际UI验证刷新滚动定位。列表/网格偏好须事务持久化并关闭重开验证。打开时间由成功打开后的调用者提供非负毫秒时间，不由请求/失败打开更新；时钟回拨时保留最大历史打开时间。

本轮不更新正文修改时间，不切换正文save目标，不将元数据patch称保存成功。双端普通UI、持久化、并发重试、冷启动偏好恢复及整项LIB-04/05验收仍待。

## 实际结论

采用为后续元数据事务与列表消费者的共享规则。新增10项共同测试通过，共473项JVM XML零失败，shared本轮执行、canvas复用；[绑定报告](../reports/library-view-rules.json)。可移植性与架构检查通过。没有平台App改动，不重复构建无变化APK，不宣称移动端性能或双端运行。
