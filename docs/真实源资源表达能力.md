# 真实源资源表达能力核对（2026-10-27）

依据原开发执行计划C–F允许的只读样本工作。旧工程只读，未复制源PDF/图片/字体到新仓或发布；这里只提交路径、大小、SHA-256及能力元数据。检查器[inspect_source_assets.py](../tools/inspect_source_assets.py)显式接收本地路径，[报告](../reports/source-asset-inspection.json)绑定实际输入hash及检查器。输入不随仓库分发，因此不能把缺少本地源文件的CI误称通过。

| 真实本地输入 | 实际检查结果 | 对正式表达的要求 |
|---|---|---|
| 旧工程产品PDF，767885字节 | 严格解析8页，约595.92×841.92点，原CropBox/MediaBox和rotation/UserUnit逐页记录；使用Type3字体 | PdfPageRef保留不可变源hash及page index/box/rotation；源内部字体由PDF引擎解析，不替换为宿主字体，不把页面转成笔迹 |
| 旧封面JPEG，97320字节 | 解码1240×1754，RGB，EXIF方向1 | 保留编码原件；记录原始像素尺寸及方向/显示变换，解码派生结果不成为原件 |
| 旧图标PNG，1154字节 | 解码44×44，RGBA，alpha范围0–255 | ImagePayload须保留透明语义及裁剪/对象变换；不能默认转RGB或白底压平 |
| 旧Inter-Regular.ttf，411640字节 | sfnt目录17表，unitsPerEm2048，OS/2 fsType0 | 文件hash/字体选择策略/授权来源分别记录；技术标志不能代替许可证；未验glyph覆盖、shaping或跨端布局 |

主机pypdf逐页读取结构，Pillow真实解码图片；Poppler只渲染第1/8页至最大1200像素，肉眼检查两页中文字、表格和流程图可见且未发现裁断。只检查两页，报告full_visual_review保持false；不声称全部页视觉、坐标对齐或字体替代等价。渲染文件留在build唯一目录，hash记录于报告，不提交源内容或渲染图。所有输入检查前后hash一致。

## 采用与剩余缺口

采用源文件原字节不可变、页面引用保存源坐标语义、图片方向只应用一次且保留alpha、字体授权与技术标志分离。PDF样本含Type3，后续正式PDF平台支持矩阵必须包含该来源类型，不能用只含Helvetica的synthetic结果代替。图像方向样本目前只有1，EXIF非1/ICC/高位深、损坏/超大载荷仍需正式解码器的拒绝与显示策略。

现有common预览只有笔迹，尚无正式PdfPageRef/ImagePayload/TextPayload或生产Resource模型。此次证明本地主机能够读取指定原件，并识别正式格式必须保留的属性；没有把检查器集成App，也没有实现PDF导入/批注/导出、图文编辑、字体打包、旧JNotes迁移或双端交换。C1后在原DEV-041/043对应的正式存储与对象模型实现这些属性，不创建第二份文档authority。完整C1/M-1及DATA/PDF/OBJ需求状态不因此晋升。

命令使用bundled Python（含pypdf/Pillow）与Poppler：

```text
python tools/inspect_source_assets.py --pdf <原PDF> --image <原JPEG> <原PNG> --font <原TTF> --pdftoppm <pdftoppm.exe>
```

此入口是只读诊断，64MiB单源/500页/3200万图像像素和1200像素渲染边界仅约束本次检查，不是产品支持上限。下一工作按正式对象/格式设计核对真实旧笔记容器，保留来源版本与不支持类型，不能以当前笔迹preview reader冒充JNotes解析器。
