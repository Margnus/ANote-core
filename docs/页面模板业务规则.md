# PAGE-01 页面模板业务规则

## 交付卡

起点Core 1392d93。复核发现已有四种PaperKind、PageDescriptor、SetPaper、历史及codec，不重复建立页面模型。目标：统一A4/屏幕比例预设，在原authority中改变背景/尺寸，保留笔迹和页身份；屏幕比率输入异常不得产生命令。依据PAGE-01，LIB-01及M-1/C1/生产存储前置不改。范围为internal共享规则和原命令/历史/codec集成验证，不改普通App、格式或公开SDK。

验收：四种纸张均可解析A4与屏幕比例；沿用既有预览595×842坐标（取整点数，不声称精密物理A4），横版交换两边。屏幕预设以创建时可用编辑视口的同单位宽高计算，短边归一595，保持方向/比例；零/负/NaN/Inf拒绝，计算后超出PageDescriptor的1..14400拒绝，不截断。有限极大同值输入不因中间乘法溢出而误拒绝。

规则产出原SetPaper，绑定root id/revision/pageId/opId，交给原唯一authority提交；无新authority。原root不变，背景不写成笔迹，规范对象、采样、坐标、笔刷、transform保持；撤销/重做和原codec往返保留纸张及尺寸。坏页/坏视口不产生命令，旧revision仍由原提交规则拒绝。

## 接入责任

屏幕比例是创建时的页面尺寸决定，不是每次旋转/键盘/分屏自动改文档；后续视口改变只更新呈现变换。平台须传入扣除工具栏/安全区后的可用编辑区，宽高同单位，不能一边pixel一边point，也不能把整个物理屏幕当已验证可用区。本轮没有读取平台视口，调用者集成仍待。

沿用四种内置PaperKind，不在本规则新增颜色/网距/字体/导出版本。现有平台背景绘制不变；正式模板规格（物理尺寸精度/样式/版本）、双端新建/选择UI、真实布局及像素、耐久保存与关闭重开仍需原产品验收。JVM codec往返不是磁盘或双端运行证据。

## 实际结论

采用为后续新建/纸张菜单共享预设解析，保持原命令与唯一authority。新增5项共同测试（四种纸张均覆盖）通过，共506项JVM XML零失败，shared本轮执行、canvas复用；[绑定报告](../reports/page-template-rules.json)。可移植性/架构检查通过。无平台App变更，不重建未变化APK；未声称双端像素、平台视口或磁盘重开验收。
