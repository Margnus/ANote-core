## 工作准入、采用与停止

1. 新工作必须指向上述一个主要决策问题，列出将改变哪个结论、实际 App 消费点和足够作决定的证据。没有缺口时复用原报告，不新建同义 PoC。
2. 原则上先完成正在执行的原宿主交接；其他实验只在它受阻且能关闭独立缺口时进入。达到既定决定条件后记录采用/调整/淘汰及接入动作；证据不足就明确缺测，不以更多相似测试延长同一步。
3. 已通过子范围按代码/产物/平台保持；影响相关依赖才复验。不要让所有历史实验与 HEAD 强制同 hash，也不能把历史通过扩展到已改变的消费者。
4. 对已采用方案，优先验证同一原宿主的完整责任链。若继续使用测试专有状态机，应说明为何尚不能提炼接缝以及下一集成动作。

## 设备与指标阻挡

分别记录输入语义、输入处理时间、物理触笔到光子、呈现帧、CPU/内存、持久恢复。某数据源无效时拒绝依赖它的指标，其余仅在自身证据独立有效时采用。CPU耗时不能替代显示延迟，RSS不能补齐GPU/总内存，App完整帧子集不能缩小原分母。

同一厂商异常没有新假设时停止重复同配置采集，转可验证的设备/profiler/外部视频或继续原宿主独立工作；方法变化须记录测量范围、可比性及仍缺字段。不可用就保持对应门禁待验，不降低标准。Mac 再锁屏时沿已有授权延后相关 UI 项。

## 联合评审回执

一次评审固定源码/构建输入、Android/Apple 产物摘要、样本和支持矩阵，逐项写出结论、证据、未覆盖及后续产品验收责任。只有六项满足原门禁才能形成冻结 ADR 并进入生产 DEV-041。待验行不能标成通过；本次文档整理没有作架构冻结、性能验收或生产存储放行。
