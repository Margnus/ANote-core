# C1架构冻结前的未决事项

38个JVM测试仅消除了部分语义不确定性。以下未决项仍阻止生产架构冻结，不以当前参考原型代替最终设计。

| 事项 | 当前原型 | 冻结前所需证据 |
|---|---|---|
| 场景完整性 | 只有StrokeObject，没有真实Layer/资源/文本目录 | 层删除与pending笔、跨页复制、资源缺失和对象版本校验规则 |
| 文档唯一权威 | 单Scene内存单owner，未处理多窗口线程 | 文档级协调器、外部修订/元数据命令、typed async结果与强制调度测试 |
| 样本协议 | 合成轨迹0.1-draft，已有公共回放与JVM JSON消费 | 历史批次、预测纠正、多pointer、CANCEL、坐标快照和单位映射 |
| 保存与撤销 | 内存journal计数上限，Map复制 | durable回执、字节预算、失败补偿、长笔checkpoint、结构共享与undo |
| 索引/几何 | 只有包围盒/仿射，不是三笔刷渲染 | 规范笔刷版本、尾段拟合、命中reference、grid/R-tree分布基准 |
| 资源生命周期 | LRU只统计resident bytes | 同步/后台/GPU lease、in-flight总预算、延迟读者与close测试 |
| 平台呈现 | 只有frame token匹配 | 原生surface重建、线程绑定、IME/导航和相同几何下的后端比较 |
| 工具链与平台 | KMP2.2.21/Gradle8.14 JVM验证；Xcode27/Swift6.4可查询 | Apple兼容组合、Native编译与实际Android/iOS输入PoC |
| 旧数据映射 | 已有源码/proto定位，未运行转换 | 字段默认值、AAR版本对应、合法样本的几何与资源对照 |
| 公共API与格式 | prototype命名空间、临时数值限额 | 能力/降级、算法/文件版本、消费者回归、未知对象保护 |

推进方式：优先D2输入schema和回放，再用D3内存假后端/调度器把线程与资源契约具体化；D4验证平台限制后，重新评审统一模型和依赖DAG。任何选择改变，先更新ADR与反例，再换实现。不能以GPU、线程池或数据库库名代替证据。
