API26–32保留完整Path，不提高minSdk，不以该候选冻结生产GPU后端。GPU/heap/M-1、任意变换、owner完全丢失/跨线程移交、跨端DEV-036、完整C1及SQLite未验收。

## DEV-035历史最小App接入可行性结论

**DEV-035时不足以支持普通App最小后端切换；当前iOS状态见上方DEV-036D，Android仍未切换。** 阻挡来自代码契约，独立于是否有物理设备：

1. `canvas-core/src/androidMain/.../AndroidBrushImagePoc.kt::draw` 拒绝 `canvas.isHardwareAccelerated`；`InkCanvasView.onDraw` 未强制软件目标。不能删除检查或关闭硬件加速来假定生命周期/性能已解决。
2. `ios-app/NoteCorePreview/AppleBrushRenderExperiment.swift::AppleBrushImageExperiment.draw` 要求 `context.data != nil`；`NativeInkCanvas.swift::InkUIView.draw` 的 UIKit 当前context不保证此条件。直接调用可能拒绝展示。
3. `BrushRenderJobPoc`/Apple `submit(stroke:)` 是单笔单tile，普通App循环规范页z序绘制整页。没有完整页帧集合/缺tile判定；不能发布已到达的一部分并静默漏笔，也不能逐段重复应用透明度。
4. Android `onDetachedFromWindow`、Swift `dismantleUIView` 当前仅取消输入；Model关闭仅承担既有保存责任。没有仍可达的渲染owner驱动迟到结果drain/ACK与UNKNOWN holder协调。不能在View析构或导航清空引用时丢弃责任。
5. Android库持有器是internal，App模块不能直接消费；Swift桥接公开仅因Objective-C导出。不能为“能调用”而无约束晋升为生产SDK。作业资源池也未涵盖页目录/完整合成缓存与平台隐藏分配。

因此本轮交付审计/缺口修复与以下可执行接入设计，不包装新App、不扩笔刷导入，不增加另一个实验渲染栈。

### 文件与调用顺序

- `shared-core/.../PagedPreviewNotebook.kt`：通过现有 `snapshot()` 取不可变root及当前PageId/layer，继续由原owner写入；派生帧仅引用快照，不另建Scene或内容revision。帧身份组合document/session、page/layer、root/object revision、viewport/surface generation及采样参数；页选择、resize、缩放、导航都推进展示generation。
- `canvas-core/.../BrushRenderOwnerPoc.kt`、`BrushRenderExecutorPoc.kt`及Apple桥接：在原作业路径内扩展有界页帧计划，按规范z序完成每笔union再source-over。页目录、候选/工作/RGBA/合成输出/native副本都先准入；所有必需tile成功才标完整。Android实验接口保持受限，不通过公开一组PoC类型扩成SDK。
- 调度继续由既有有界执行器负责，owner持有帧集合与原ResourceLeasePool，禁止追加旁路生产队列。Apple adapter当前创建既有执行器实例，但不等于已借用PreviewModel的存储实例：实现时明确注入/共享调度或受限render实例的归属和总额度，避免在View重建时增生worker。不得在receive内提前结算；drain返回后ACK才可创建/发布holder。
- `android-app/.../InkCanvasView.kt`及`ios-app/.../NativeInkCanvas.swift`：平台边界先在CPU bitmap context消费holder形成不可外借的完整静态图。真正View目标的复制/显示须另有明确的引用持有与释放证明；不能把CPU图像“再画一次”视作GPU fence已通过。首个可交付子范围可限定CPU离屏目标，但那不是普通App接入验收。未证明真实目标前保持既有绘制。
- `MainActivity.kt`/`NoteStore.kt`和`NoteCorePreviewApp.swift::PreviewModel`：render责任归原main/document owner；View只借帧。关闭先停止准入/取消工作、使frame失效，保留adapter与holder到迟到结果ACK、native引用确认及pool drained。导航可先返回，由原owner有限批量pump到完成，不能阻塞UI等待worker，也不依赖旧View存活。UNKNOWN保留责任对象和charge，禁止超时当释放、破坏性重试或另建owner接管。

### 发布、失败与退出

同页同内容同视口的完整上一帧可暂留；视口变化只在验证过的变换范围内复用。页/内容变化不能展示过期holder。静态帧未完成时使用既有规范Path渲染整页作为唯一可见结果，或明确保持加载/错误状态，不能把半张新帧与旧内容混合。动态笔保持原输入路径；提交后待完整静态帧包含该对象才同时撤下动态覆盖，避免空隙或双重alpha。拒绝/取消/错误不改规范样本、保存版本或支持笔刷范围，已接受笔仍可保存/重开。

运行验收须在对应新包分别记录：真实View可见像素对照；同笔自交alpha及多笔z序；快速切页/缩放/resize后迟到拒绝；拒绝/失败完整回退无漏笔；返回/再开、后台及旧View销毁后责任仍可drain，最后确认释放归零；UNKNOWN故障保留账本；保留既有文件与不支持笔刷拒绝。Android用专用5580、iOS用专用7F2A…实际宿主与CUA Device Hub交互，XCTest后恢复普通payload；新包UI证据单列。真机帧/heap/触笔和GPU仍须M-1/相应后端验证。

调整条件：真实View需要不可证明的GPU引用生命周期、目录/合成峰值超预算、整页性能不可接受或无法保留关闭owner，则停止该接入路线，保留普通Path并记录具体失败。可先完成页帧/关闭协议的实际宿主验证；不得转为更多独立单笔PoC或把单元数量当接入验收。
