# 三笔预览链路候选设计（DEV-042 E3，2026-11-17）

需求映射：INK-01（基础笔与荧光笔）、INK-02（颜色粗细与常用笔）的候选设计。本文属于产品广度推进计划路径 2 的"C–F 不连接生产的格式/迁移设计"，不开放 App、不修改 v2 生产格式、不提升需求实现/验收状态。正式算法版本评审属 C1 第 2 项剩余出口。

## 一、现状证据（源码锚点）

| 事实 | 位置 |
|---|---|
| codec v2 的 S 行已序列化 `brush.kind.name`、`algorithmVersion`、`argb`、`width`；三笔字段在格式层已可往返，**无需格式扩展** | shared-core `PagedPreviewCodec.kt:168,250-251` |
| codec 读取与写入均要求 `brush.algorithmVersion == 1` | `PagedPreviewCodec.kt:169,192` |
| 预览落笔硬编码 `BrushSpec(BrushKind.MONOLINE, 1, width, color)` | `PagedPreviewNotebook.kt:329` |
| `PreviewEdit.SelectPen` 仅携带 `argb/width`，无 kind | `PreviewEdit.kt:7` |
| 三笔共同几何候选使用 `ALGORITHM_VERSION = 2`，其他版本拒绝 | canvas-core `BrushGeometry.kt:42,57` |
| 跨端三笔正文已有读取/重导出往返证据 | `docs/C1未决事项.md` 2026-11-14 证据复核（API26/32 读取并重导出 Apple 两页三笔正文） |

结论：三笔接入的真实缺口不是格式，而是（a）工具选择参数、（b）落笔 kind 来源、（c）算法版本 1 下的显示语义、（d）渲染端三笔消费。

## 二、算法版本语义候选

| 方案 | 内容 | 取舍 |
|---|---|---|
| A 限定开放 | 算法版本 1 下：HIGHLIGHTER 定义为"等宽 + 半透明"；PRESSURE 在版本 1 不开放，待版本 2 几何接入后开放真实压感宽度；MONOLINE 不变 | 荧光笔低风险先落地；避免"等宽假压感"破坏用户预期 |
| B 严格等待 | 三笔统一等 C1 第 2 项版本 2 几何评审后进入预览 Notebook | 最保守，但荧光笔被无必要拖延 |

推荐 A 的限定子集：版本 1 仅增加 HIGHLIGHTER 一种新 kind；PRESSURE 仅在版本 2 接入后开放。版本 1 的 HIGHLIGHTER 显示语义（等宽、alpha、叠加规则）必须写入验收并双端一致；E1 橡皮命中已按 `brush.width` 统一处理，与荧光笔宽度语义一致，无需另建命中分支。

## 三、后续实现颗粒度（均需逐卡验收，App 开放另行决策）

1. **E3b 工具选择扩展**：`PreviewEdit.SelectPen` 增加 `kind`（默认 MONOLINE 兼容旧调用）；非法 kind/版本组合类型化拒绝；落笔 kind 来自抬笔捕获的 `StrokeTarget`，不在 IO 完成时查当前工具。Android/iOS 调用处同步迁移，需避开并行会话冲突。
2. **E3c HIGHLIGHTER 显示接入**：双端软件 Path 渲染对 HIGHLIGHTER 应用约定 alpha 与等宽；规范内容（样本/宽度/颜色）不变，仅显示语义扩展；保存重开与跨端交换后 kind/alpha 一致。
3. **E3d 常用笔槽偏好规则**：3–5 个常用笔槽（kind/argb/width）的持久偏好规则与重开恢复；仅应用偏好，不进文档格式。2026-11-27 已补 E3f 宿主接入：同一 `PenSlotRules` v1 偏好编码由 Android `SharedPreferences` 与 Apple `UserDefaults` 存储，双端预览 UI 选择/更新/重置笔槽，进程重启后恢复；文档 codec 与 PRESSURE 关闭语义不变。
4. **E3e PRESSURE 版本 2 接入**：待 C1 第 2 项评审，使用 BrushGeometry 版本 2 的真实压力宽度；样本压力原值保留，派生几何可重建。

## 四、验收草案（E3b/E3c 实施时展开为测试）

- SelectPen 扩展后：未知 kind、非支持版本、非法宽度/颜色均类型化拒绝，原选择不变。
- 落笔 kind 与抬笔捕获一致；撤销/重做后 kind 保持；关闭重开 codec 往返 kind/algorithmVersion/argb/width 不变。
- HIGHLIGHTER 双端同一样本的 alpha 与等宽显示一致；叠加两次不透明度行为有明确定义。
- 整笔橡皮（E1）对 HIGHLIGHTER 命中与 MONOLINE 同路径（已有测试覆盖）。
- 跨端交换含 HIGHLIGHTER 的文档，对端读取/重导出字节保持。

## 五、开放条件与风险

- 版本 1 新增 HIGHLIGHTER 属"新笔刷开放"，按现行规则需用户确认预览链路开放策略（产品广度推进计划门禁决策项 1）；未确认前仅保留本设计与后续 internal 候选。
- PRESSURE 显示预期、版本 1→2 的算法迁移、任意变换下的宽度语义均属 C1 第 2 项，不在本设计擅自冻结。
