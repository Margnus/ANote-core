# 资源文件与数据库联合提交恢复边界（隔离设计验证）

2026-10-27，沿蓝图05“文件与数据库联合提交”和现行计划的C–F独立业务样本推进DATA-04/05/08。本文件不选择生产schema，不连接App、预览文件或文档authority；不能据此放行C1或DEV-041。

## 当前采用的责任顺序

1. 先持久记录进行中导入任务的身份，再在任务独占staging写入；完整关闭、大小和hash校验前不创建可见Document。
2. 完整资源以不覆盖方式promote。在本机探针中使用同一临时卷上的hard link完成no-clobber创建，已存在同内容只复用，已存在但损坏则明确REPAIR_REQUIRED并保持原字节。该API只是主机反例方法；2026-10-29实际API36 App域已拒绝hard link，不能原样移植。Apple模拟器仅有同卷候选事实，不批准移动端生产promote port、目录fsync或最终文件协议。
3. 同一SQLite事务写Resource元数据、Document引用、Operation身份与任务完成状态。只有该事务提交后，此样本的document查询才可见新记录；没有“先显示文档、再补资源”的半状态。
4. 回执丢失时先读Operation并验证文档/hash一致及实际资源完整性。相同操作只重放已提交结果；身份冲突拒绝；资源已坏不能仅因DB里有Operation就宣称成功。
5. promote后DB尚未提交时，完整资源可能存在而Resource表还没有行。进行中任务必须保留目标hash，恢复及GC不能只扫描Resource/Document表便判孤儿。探针证明恢复记录存在，未实现最终GC与导入写者互斥；扫描器仍必须完整枚举任务并在真正退休前重新协调。

## 实际边界与期望

| 子进程退出点 | 重新打开后的可见状态 | 责任与恢复 |
|---|---|---|
| staging半写 | 无Document/Operation；任务running；只有不完整stage | 不误promote或提交。重试使用另一次stage，原任务/源载荷保留。 |
| 完整stage已fsync/关闭 | 无Document/Operation；任务记录hash | 可重新校验并promote，未显示成功。 |
| promote完成 | 资源文件存在，Resource/Document/Operation尚不存在；任务running+hash | 任务持有恢复责任，不凭“无Resource行”回收。重试不覆盖完整资源。 |
| DB事务未提交 | 资源文件存在；实际进程退出后DB回滚到无Document/Operation | 保留任务及资源；相同操作重试提交一次。 |
| DB已提交但回执未返回 | Resource/Document/Operation各1，任务complete | 相同操作返回ALREADY_COMMITTED，无新stage/文档/操作。 |

另验证3条：预存在错误字节的hash地址拒绝覆盖且无文档可见；同一operation换文档拒绝且不stage；已提交后人为损坏测试资源，再次重放明确要求修复，数据库状态和损坏文件都不被悄悄重写。所有原source.bin载荷保持。这里的“可见”仅临时SQL查询，不是资料库UI或生产保存标记。

## 仍未实现或未验证

没有真实PDF/图像/字体导入、生产事务schema、跨操作去重/并发导入、任务取消与安全过期、读者pin、资源文件退休或GC删除、跨进程最终删除协调、文件退休途中崩溃恢复、备份及资料库可见性实现。没有目录fsync、平台原子文件替换、Android/Apple联合提交或断电证据；os._exit是进程中断，不是断电。主机SQLite版本和hard-link能力不能替代两端port选择。

采用的出口仅是原联合提交设计的失败/恢复责任和固定反例。DATA-05、DATA-08仍未开发/待验收，DATA-04仅部分实现；完整C1/M-1、DATA-05/LIB-08等依赖及DEV-041生产门禁保持。下一实际出口是任务取消/过期与资源退休的最终协调设计，必须保持源资源和已有有效引用；不能把此探针复制进App当作存储实现。

## 任务取消的采用边界（2026-10-27）

同一隔离probe追加五类固定反例：半stage退出后取消、promote退出后取消、已提交后取消、真实活跃生产者、退出旧attempt被新生产者替换。取消请求只置cancel_requested，不释放running责任。取消确认必须匹配active_attempt且原进程明确结束；仍活跃/无法确认时拒绝。原生产者在关闭stage后或提交事务前可协作确认取消，之后不再publish。已提交操作优先返回ALREADY_COMMITTED，不能改写为cancelled或撤销文档。普通重试不能复活cancelled任务，也不能在原生产者仍活跃时抢占。

两个真实Popen消费者由ready/release门控制：取消请求后仍持有stage且拒绝外部退休，旧attempt的请求与确认不改变新attempt，再放行原生产者自行确认并等待进程结束。半stage及promote退出路径确认取消后仍保留文件；没有Document/Operation/Resource行，不代表文件可直接回收。

采用“意图→生产者停止发布/确认→取消终态”的责任顺序，拒绝超时自动清引用。这里Windows只读OpenProcess/GetExitCodeProcess、POSIX信号0仅为主机夹具保守观察，未知身份拒绝退休，PID复用可能保守阻塞；不是生产跨进程身份协议。10秒夹具等待超时只异常退出并保留running责任，不是过期策略。生产取消UI、可靠attempt能力、reader pin、最终GC协调、目录同步/断电及移动端语义仍未实现。5退出+3完整性/身份+5取消分别计数，不晋升DATA需求验收。

## 移动系统不覆盖链接的采用/否决（2026-10-29）

[实际报告](../reports/resource-promote-platform.json)、[执行器](../tools/verify_resource_promote_platform.py)只在唯一cache范围使用65539字节合成载荷。stage先完整写入、同步并关闭，然后调用系统API；没有数据库或NoteCore业务链接。

| 实际环境/入口 | 结果 | 决策 |
|---|---|---|
| Android API36 ART、`runas_app`、`Files.createLink` | 新目标立即`AccessDeniedException`；stage原hash/65539字节保持，无目标 | 不能将run-as限制直接推广到App；原失败保留，再用独立App域核对。 |
| 同API36、唯一独立APK、真实`untrusted_app`域、同API | 新目标同样拒绝；完整stage保持，无目标；安装/执行/移除回执均保留 | **否决该Android hard-link候选**。冲突与link后恢复不可到达，不伪记通过，不关闭系统限制。独立APK不替换NoteCore，不把它称作原App生产port。 |
| iOS27模拟器独立Swift、`FileManager.linkItem` | 新目标同inode/device/hash；删stage后目标完整；已有完整和损坏目标均Cocoa516/底层EEXIST17拒绝、双方原字节/身份保持 | 仅采用这个模拟器同卷文件系统的候选子范围。它未进入iOS App沙箱消费者，不代表物理iPad/文件provider。 |
| Apple链接后、清stage前`SIGKILL` | PID18784实际终止，新PID18794核对stage/target同inode/hash且完整；独立用例PID18773 | 保留“进程死亡后链接仍可恢复”的事实，不等于目录同步、断电或设备持久性。 |

完整载荷SHA256为`ce8ab5e02d52b9d74227078ca655d336386fcdd6774f476832593582722d6b32`；损坏目标固定3字节，始终保留损坏hash，不自动修复。实际stdout/stderr、API错误、执行域、PID、编译参数/SDK指纹与可执行文件均绑定在报告中。首次Swift探针语法失败发生在执行前；初次Android拒绝与后来真实App域证据分开保留，不将工具编译失败当App缺陷。

原Android66/Apple16逐文件hash、Android普通APK、Apple完整payload/noXCTest与普通PID前后完全一致，独立探针APK已移除。没有重建NoteCore/Swift普通包或改共享业务，因此不机械重跑已有平台套件。架构与可移植性检查另执行。
