# PDF-02 当前页与邻页任务准入

## 交付卡（2026-10-29）

起点Core4f9eafb。复用PdfPageCatalogRules的完整同空间/文档/元数据版本校验及稳定pageId/源hash/index，不新建调度器、worker、缓存或内容authority。目标：当前PDF页任务优先，最多预取相邻前/后各一页，空白页不请求PDF渲染，过期任务选择显式失效。现行计划允许隔离规则，PDF-01/M-1/C1/DEV-041依赖不变。

验收：任务顺序当前页→下一页→上一页，预取额度允许0/1/2，不能跳过空白邻页去找更远PDF页。空白当前页仍允许其直接PDF邻页预取；源页索引保持原值，同一源页对应不同文档pageId仍是不同目标。计划绑定space/文档/root revision/元数据revision/当前pageId/预取额度，任务带源hash/index；验证时完整重算比较，切页/重排/版本或源引用变化显式STALE_PLAN。未知当前页/非法额度/坏快照整次拒绝。

计划只是原有队列消费者的输入：后续在原worker/预算系统先保证当前页，再按剩余预算准入邻页，当前页也可能因真实资源预算拒绝；本规则没有接收或取消工作，不管理native资源，不把输出任务列表叫已渲染/已显示。切页时原队列须取消未运行旧任务，运行/已交付任务按原owner/资源回执退休，不能仅因STALE_PLAN就释放未知读者或丢已接受输入。PDF背景任务不得阻塞书写队列；需实际平台执行验证。

采用后仍需renderer port、尺寸/tile/资源总预算/取消与发布token接缝、真实PDF当前页/邻页表现、双端UI与性能验收。PDF-02保持未开发/待验收，不继承旧系统renderer报告为本规则运行证据。
