# AI开发实施规范

2026-10-15，按用户确认的协作方式制定。本文件调整执行方法，不代表新增功能已实现或既有门禁已通过。

## 执行原则与文档分工

采用“整体规划、分阶段验收、阶段内连续自主开发”。全局计划明确产品边界、依赖和阶段出口；只把近期里程碑展开为可执行步骤，详细设计随证据更新。一次授权可以覆盖完整里程碑，无需用户逐函数指挥；整个跨端产品按里程碑推进。

| 文档 | 职责 |
|---|---|
| AI-Note蓝图及需求表 | 产品范围、需求编号、总体架构、阶段目标和需求验收 |
| 本文件 | AI协作、任务粒度、验证、审查、提交及交接规则 |
| [开发执行计划](开发执行计划.md) | 将蓝图转换为交付顺序与依赖；历史节点保留原范围 |
| [当前开发状态](当前开发状态.md) | 最新基线、正在实施的里程碑、证据、未决门禁与下一步 |
| docs/adr、专题PoC文档及reports | 决策理由、实验方法及真实证据 |
| AGENTS.md | 精简持久约束及入口，不复制全部历史 |

继续开发先检查两仓Git状态及远端差异，再读当前状态和相关设计。保留用户及其他会话未提交的改动。实现仓库维护执行进度；蓝图仅同步影响产品范围、架构和阶段决策的变化，并链接执行入口，不重复逐次测试日志。

## 任务粒度与连续执行

- 简单界面、明确业务和规则固定的批量修改：一次完成整个功能及相关检查，无需大型计划。
- 跨模块功能：按用户操作闭环交付，例如“创建多页文档→书写→切页→保存→退出→重开”，同时覆盖界面、共享模型和平台适配。
- 并发、渲染、文件格式和同步：先明确假设和退出条件，用最小实验获得决策证据，再扩大实现。
- 一个里程碑可含多个内部任务；实现→测试→修复→差异审查→记录→已授权提交推送连续推进，不因一次汇报、一个类或一组测试就停止。
- 真实阻挡、需要用户决定的产品取舍或执行环境/预算限制才中断依赖工作。报告完成范围、阻挡及恢复入口，继续独立可做的工作；不冒充全部完成，不承诺没有调度支持的后台持续执行。

任务大小以可独立验收、可清楚审查为准，不固定代码行数、文件数或聊天轮数。AI执行时间不替换原团队人力估算。

## 里程碑卡：编码前明确结果

在“当前开发状态”或链接的执行文档维护当前卡片，复用DEV编号及需求映射，不另建重复台账。简单任务可缩短：

```text
里程碑：编号 / 名称
目标：用户行为变化，或需要得到答案的关键风险
依据：需求编号、相关ADR、起始提交；映射不表示需求验收通过
范围：本次交付及不扩展的内容
依赖：前置证据、平台/设备/环境；缺失时可独立推进的工作
实现路径：少量有顺序的步骤、跨模块接口及责任边界
验收条件：可观察结果、异常行为、数据保留和回归要求
验证方法：命令、平台、样本、对照；性能先测基线再确认门槛
交付物：运行入口/产物、差异、报告、决策及下一步
调整条件：何时缩小范围、放弃方案或请求产品决策
实际结论：通过/部分通过/待测/阻挡，证据及对应提交/产物SHA
```

例如“支持保存”应明确：实际写入确认后显示已保存；失败保留最后确认版本与待重试内容；旧写回不覆盖新状态；重开读取正确；格式往返保持规范内容。强停、写入故障、进程崩溃和断电是不同验证范围，不能互相替代。

## PoC退出与App集成

每个PoC开始前明确问题、候选方案、输入/预算、正确性对照、成本测量、足够作决定的条件及接入/淘汰路径。已有实验优先补齐影响决策的证据，不为增加测试数量无限扩展旁路模型。

结束时记录“采用、调整后采用、放弃或证据不足”及理由。证据不足须写明缺失测量及下一实验；证据足够就形成决策。每次收口说明解决的风险、实际App是否消费该实现、接入缺口及下一个可运行增量。晋升生产实现仍须通过相应平台、生命周期、存储及架构门禁；C1前实验保持internal，不因PoC通过就开放新笔刷/格式。

当前继续遵守ADR-0020：旧栈收口→M-1物理设备基线及M-2/M-3关键PoC→依证据修订架构→C1评审→SQLite生产存储→生产闭环。设备未就绪可推进独立实验、样本及集成设计，依赖该设备的门禁仍待测。进入生产闭环后，每个产品里程碑应提供可体验增量。

## 验证、审查与完成定义

| 改动风险 | 对应证据 |
|---|---|
| 共享规则与格式 | 公共语义/异常测试、规范内容往返；涉及Native行为时跑原生目标 |
| 原生输入、UI及平台API | 对应平台实际运行和关键操作；编译不能代替运行 |
| 生命周期、并发与资源 | 真实执行器，迟到/取消/关闭/交付失败及责任保留反例 |
| 持久化与迁移 | 实际写入重开、失败重试、旧数据保留、损坏拒绝及相应恢复验证 |
| 渲染和性能 | 正确性oracle/图像对照、固定样本及测量方法；物理延迟/heap/帧在目标真机测量 |
| 文档与计划 | 差异、链接、范围及约束一致性；纯文档修改不重跑App全量测试 |

先跑相关检查，关键跨模块/双端集成再做必要完整回归；除非新改动、失败或新证据要求，不机械重复。测试验证行为和关键不变量，避免只复述实现；不为通过测试而弱化契约。

提交前审查数据丢失、幂等、身份/修订、线程所有权、资源释放及兼容性。重大格式、存储和并发改动安排与实现分开的审查步骤，从需求及失败场景重新核对；条件允许时独立审查，但工具通过不保证正确。

完成里程碑须同时具备：范围内行为实现；适用验证通过；差异已审查并修复实质问题；当前状态更新；已授权提交推送完成。缺设备或平台证据时，只记子范围完成和待测项。报告关联源码/产物版本；不相加不同平台测试次数作为需求完成数，不用实验报告证明未接入App的行为。

## 并行协作与用户决策

规范模型、文件格式及提交/保存语义由同一责任方统一。接口稳定后，Android、iOS和测试可按不重叠范围并行，明确文件边界、输入输出、依赖和最终集成验收。只有用户明确授权或适用仓库规则要求时启动子代理，本规范本身不启用子代理。

AI自行处理授权范围内可逆的实现细节、修复、测试及已授权提交。用户主要确认产品取舍、体验和重要架构决策。新增产品范围、破坏性格式/数据变更、需要用户操作设备或尚未授权的发布，先说明影响及依据；已有授权不重复索取，不通过降低完成条件掩盖失败。

## 后续推进指令

> 依据AGENTS.md、当前开发状态和AI开发实施规范，推进下一个可独立验收的里程碑。先明确范围、依赖和验收条件，然后连续完成实现、相关测试、问题修复、差异审查及已授权的提交推送。普通实现细节自行决定；涉及产品取舍、破坏性格式变更或需要我操作设备时说明影响再找我。交付运行入口、对应版本的验证证据、剩余限制和下一步；不要以新增代码或单元测试通过代替产品验收。
