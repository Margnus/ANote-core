# 原派生路径的数值塌缩拒绝

2026-11-10，C1第2项/ENG-03，基线 `48ebcd5`。修复现有 `BrushPathPoc` → `ReducedBrushPathPoc` → `ChunkedBrushPoc` 原掩码链路的派生几何失败边界，不增加规范模型、算法版本、普通App笔刷或生产格式。

## 反例与原链路修复

合法正宽度不保证派生轮廓可表示：`Double.MIN_VALUE` 等宽笔或 `1e-323` 的零压力笔半径会下溢为0；在 `(1e9, 1e9)` 上宽度 `1e-8` 的点笔，各顶点可能舍入到同一位置。原生成器仍返回 Ready，原掩码调用也返回 Ready，而不是明确拒绝。源样本和解析包络仍在，包络中心命中反例保持；不能把退化轮廓当成成功生成的可用墨迹。

先新增原调用反例与正对照并实际运行：15项中2项失败，路径及原掩码的拒绝断言失败，可表示极小/远原点轮廓对照通过。原源摘要、失败XML与构建日志保留于[before](../reports/path-precision-rejection/before/source.json)。修复前后测试源码相同，未放宽拒绝要求。

修复在原预扫阶段拒绝半径下溢，在每个轮廓完成后、Ready发布前检查有限顶点、相邻顶点重复、非零面积及全部轮廓方向一致。面积先平移并按局部尺度归一，避免对可表示的 `1e-200` 半径量级轮廓直接平方而误判0。反射可令所有轮廓共同反向；剪切、正常点笔及原黄金/掩码/资源消费者保持。检查可取消，不发布部分路径。

下溢返回 `radius-underflow`，无法形成可验证轮廓返回 `coordinate-precision`，复用原 Rejected/Cancelled 及掩码拒绝传播，不改点、宽度、颜色、alpha、tolerance或身份。坐标精度检查发生在派生输出数组生成后，仍沿原worker峰值/ACK责任；不宣称所有精度失败都在分配前发现，也不以丢样本、调粗画笔或重建另一份正文补救。新增线性检查未做物理成本验收，不冻结性能阈值。
