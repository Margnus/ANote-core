# LIB-06 笔记移动业务规则

状态：内部位置规划器；未接普通App、生产存储或完成需求验收。

## 交付卡

目标：移动编辑中的笔记时位置变更保持同一noteId，允许返回根目录；任何拒绝不修改原快照。依据：LIB-06及LIB-03，起点fcb0040。范围：复用原文件夹快照与校验，不引入新authority、IO、SDK或内容模型。依赖：M-1/C1/正式元数据门禁不变。

验收：位置patch仅包含space/revision与同一noteId的before/after；同目录移动返回相同位置，未知笔记/目标、过期/跨空间/不完整快照、无关坏引用/循环均拒绝。六项共同测试及原目录回归验证这些边界。采用为未来唯一元数据事务的位置规则；不是保存回执。

## 接入责任

规划器不读取或改写正文、文档revision、页/对象身份、标题或编辑session。重复目录名不参与身份匹配。正文保存必须始终以spaceId/noteId寻址，不能因目录变化改文件路径或生成新noteId。未来元数据事务须核对同一空间完整revision及before行，再原子更新位置并推进revision；旧patch不能在目录删除后使用。没有事务消费者时不能声称已验证编辑期间保存、迟到保存回调或耐久重开。

本次重命名沿用既有契约，不增加第二标题规则。未来仍需DATA-01/DEV-041、双端移动UI、编辑中移动→继续写→保存→关闭重开、并发目录删除/失败重试及跨端实际运行。需求保持部分实现/待验收。
