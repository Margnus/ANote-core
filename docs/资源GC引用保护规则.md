# 资源GC引用保护规则（生产接入前的业务样本）

2026-10-27，沿蓝图[05文件与数据库联合提交](https://github.com/Margnus/AI-Note/blob/bf1a83c/05-数据与同步.md)及DATA-08验收范围，在既有开发计划允许的“C–F不连接生产的格式/业务规则/测试样本”内推进。本文件不定义生产SQLite schema，不连接预览保存或实现资源删除器，也不解除C1/DEV-041门禁。

## 规则与采用决策

- 只有来源完整、同空间、已校验且已promote的资源，在明确安全期之前、没有任何有效引用时，才进入候选列表。安全期未配置时明确拒绝；不默认套用30天或当前墙钟。
- 引用必须覆盖正文、回收站、历史、冲突及进行中任务。样本额外保留备份、outbox和未知未来owner类型；查询不能只白名单几个已知kind后忽略其他引用。枚举未完成或不支持的catalog版本均拒绝本轮回收。
- 缺失/损坏源、未完成staging、未知资源状态及缺少promote时间均保留待修复。损坏不能被误称为可再生缓存；没有把源PDF/图片/字体当缓存删除。
- 空间边界必须由调用方提供，引用按同空间与完整hash关联。资源hash相同不意味着不同账户/空间授权相同；不能跨空间清理或授权。
- 候选列表不是删除回执。列表生成后新增任务引用，重新查询必须保护该资源；事务rollback的引用不应误变成已提交引用。本样本不实现最终删除锁、资源读者pin、tombstone/rename或崩溃恢复。最终单写协调器必须保证引用提交与文件退休不会竞态，不能拿本查询直接扫描unlink。

采用上述保护条件作为DATA-08后续实现的必测业务规则；拒绝“目录无正文引用即删”“只看计数”“按文件名猜缓存”“超时清空任务引用”和“把候选列表当删除授权”。生产保留政策、schema、扫描水位、任务终态、实际文件事务及最终清理协议仍待设计与平台验证。

## 可检查的证据

[样本](../fixtures/storage/resource-gc-cases.json)声明synthetic和draft；字节是有限不透明载荷，不假装合法PDF/图像/字体或用户笔记。[验证器](../tools/verify_resource_gc_rules.py)在工作区build下生成唯一临时目录，对真实文件计算大小/SHA-256，把实际存在及校验结果写入临时主机SQLite。临时表仅用于表达反例，不能当作生产metadata迁移。

18个固定期望场景包括未知catalog版本（实际PRAGMA user_version）、未配置策略、引用枚举不完整、精确时间边界、同空间/跨空间、八类引用、损坏/缺失/staging/未来状态、迟到引用与真实事务rollback。所有场景检查源载荷在查询期间集合/hash保持；查询本身不删文件。结束只清理验证器自己创建的临时目录。

6个错误查询变体分别移除引用、年龄、校验、空间、跨空间同hash引用关联及状态保护，全部被固定反例拒绝；这用于验证样本能发现保护条件缺失，不代表随机并发/断电已测。执行：

```text
python tools/verify_resource_gc_rules.py
python tools/validate_fixture_catalog.py
```

[规则报告](../reports/resource-gc-rules.json)记录主机SQLite版本、每例候选/拒绝及源码绑定；catalog及verifyPrototype复用相同检查。18个规则场景不与437项JVM测试相加，不等同Android/Apple平台SQLite测试。

补充的文件/DB边界及进行中任务责任见[资源联合提交恢复边界](资源联合提交恢复边界.md)。隔离主机验证不改变下列生产待办。
