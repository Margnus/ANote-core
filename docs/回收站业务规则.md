# LIB-08 回收站业务规则

## 交付卡

起点Core a795fff，现行计划允许隔离业务规则；依赖LIB-03/DATA-04及M-1/C1/DEV-041不变。范围为shared-core internal纯元数据计划，不接普通App或生产存储、不引入新authority/IO。

目标与验收：入回收站保留noteId/原目录/删除时间，不删除正文；恢复到尚存原目录，否则根目录；活动与回收站身份互斥，拒绝不完整/跨空间/旧版本/损坏目录；清空必须先产生绑定space/revision的完整范围，确认后只可返回完全相同范围的元数据移除计划，新增/移除/变更条目令旧范围失效。失败保留输入；共享测试验证全部边界。

## 契约与接入出口

复用LibraryFolderSnapshot作为活动笔记/目录完整枚举，trash额外保存已删除笔记的位置历史。历史原目录可不存在，但ID须合法；活动笔记位置必须仍指向存在目录。不能把分页视图、漏掉其它活动笔记或回收站条目的枚举标为完整。总活动+回收站位置候选上限沿用100000，仅为规则准入，不是生产heap/分页性能结论。

入回收站计划原子移除活动位置并添加相同noteId的trash行；恢复计划反向变更并清除trash行。正文/页/对象ID/内容revision不在该规则中，不能因移动生成新文档。目录ID必须为不可复用的稳定身份；同名新目录不能继承原ID，未来事务/ID分配器须保持此约束。删除时间由调用者成功动作提供非负毫秒。重复操作明确ALREADY_TRASHED/NOT_TRASHED，不新增时间或复活旧请求；生产重试需事务opId回执，不以该拒绝替代幂等提交协议。

清空分两步：inspectEmpty输出按noteId稳定排序的完整trash范围，范围包含space/revision及原目录/删除时间。UI须展示数量、范围、影响并在用户明确确认后调用planEmpty，规则再次比较当前完整范围。它不是确认UI或删除授权。未来唯一元数据事务须重新核对space/revision与before行并原子应用所有位置变化；不能在校验与提交间插入新引用。产出的移除计划仅涉及回收站引用，不删除正文文件/资源；正文/历史/冲突/任务/读者pin及资源GC保护继续适用。

采用后仍需正式元数据/日志及opId重试、编辑中的删除协调、双端回收站列表/确认UI/恢复/清空后关闭重开、历史/资源保留和实际GC联动验证。非空文件夹递归删除策略不在本次笔记回收站规则中。整项需求保持待验收。

## 实际结论

采用为未来唯一元数据事务的回收站规则。新增10项共同测试通过，共483项JVM XML零失败，shared本轮执行、canvas复用；[绑定报告](../reports/library-trash-rules.json)。可移植性/架构检查通过。无平台App改动，不重复构建未变化APK；不声明双端UI、资源GC或耐久保存通过。
