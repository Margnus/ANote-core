# 原打开准入临时分配修复

2026-11-09，C1第1项原消费者路径的具体修复。范围为原 PreviewDocumentReader.accept 与 Affine2D 有限系数构造检查，不新增模型、authority、格式、公开签名、笔种或调度器。

## 实际问题与修复

原 accept 在每笔能力检查中创建6系数列表；Float量化矩阵只需要“是否存在受支持的逆”，却调用 inverseOrNull 创建了派生矩阵。两个矩阵构造器也各创建系数列表。已有 hasInverse 使用相同 withInverse 判定，可避免不需要的派生对象。

现在使用标量系数检查，Affine2D构造器同样直接检查六个有限值，并复用原 hasInverse。原系数绝对值上界、Float量化、缩放归一/行列式阈值、有限逆系数及宽度拒绝规则均保持；没有复制一套逆矩阵算法。原codec/Reader/Notebook采用链直接消费这处实现。

## 固定主机证据

新增一个JVM ThreadMXBean回归，使用5000笔、每笔一个真实样本、同一合法剪切矩阵；根和样本在测量前构造。测量一次 accept 调用的当前线程累计分配，warm-up8次后取3次最小值。该工作负载不是完整S1/S2、峰值驻留heap或物理设备性能基线。

| 输入 | 修复前字节 | 修复后字节 |
|---|---:|---:|
| 空根 | 232 | 232 |
| 5000笔合法根 | 3,400,232 | 320,232 |

修复前原1MiB dense-minus-empty回归界限实际失败；修复后通过。测试源码、上限和样本未改，旧源码指纹/固定Git基线、失败XML、修复后XML及构建日志保留于[报告](../reports/preview-read-admission/report.json)。约308万字节差值只说明本次JVM调用的临时分配减少，不能当作总预算已闭合或相同Native/ART heap收益。

完整JVM578项零失败/跳过，canvas/shared在业务修复后实际执行；最后只为Android测试选择源码绑定更新verifyPrototype时，两套JVM任务UP-TO-DATE，报告没有把它们重复记为新执行。
