# NoteCore逐步开发执行计划

2026-10-14启动。需求和总体架构沿用[完整蓝图](https://github.com/Margnus/AI-Note/blob/main/README.md)，本文件负责将其转成可连续执行的小交付。当前是C0/C1，尚未通过整体架构冻结，不批量搬运旧DrawPanel实现。

每次交付只推进一个可测闭环或风险层，不同时更换全部算法。大阶段人力估算仍见[主排期](https://github.com/Margnus/AI-Note/blob/main/07-开发计划.md)，此处不将AI一次执行时间折算成团队工程人周。

| DEV-008 | 公共输入回放 | 历史点、预测隔离、捕获target、取消/关闭、错误与容量原子拒绝、长笔保点 |

## 下一迭代拆分（D2）

已生成[候选轨迹](../fixtures/README.md)与hash清单：普通、预测、延迟切层、取消、手指导航。已通过Python格式/顺序/reference投影验证和Kotlin公共状态机→场景命令→内存authority的JSON回放；原生消费未实现，设备和实际延迟为null。这是D2部分成果，不是C0硬件基线完成。

1. 定义真实输入轨迹的schema：单位、pointer/tool、单调时间、历史点、预测点、坐标快照、设备capability。
2. 生成可重复的单笔/急转/长笔/多pointer/CANCEL/切层轨迹；合成轨迹明确标记synthetic，不能伪装真机采集。
3. 建立S1/S2/S9规模样本生成器和hash清单，记录点数/对象数/空间分布。
4. 从旧源码/proto整理笔种、点字段、默认值及版本映射，暂不导入真实个人笔记。
5. 定义原生事件与性能采集接口，排定实际设备后才填写延迟/内存基线。

D3再针对背压/lease和调度设计实现模型级测试；不把LRU驱逐通知当作GPU资源可安全释放的证据。D4完成两端工具链和实际设备验证后才选择原生渲染后端。

## 持续推进规则

下一次继续时先读取[进度](进度.md)和实际verification.json，检查源码hash与测试是否仍匹配，再进入第一个未完成交付。必要修订同步回蓝图，但蓝图中的整项需求状态不得由参考原型代替产品验收。任务结束更新实际结果、阻碍和下一具体任务；用户已授权关键节点提交并推送：NoteCore→ANote-core，蓝图→AI-Note。提交前检查差异、运行相应验证、更新实际进度；不强推、不改旧App或库。
