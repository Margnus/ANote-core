# NoteCore逐步开发执行计划

2026-10-14启动。需求和总体架构沿用[完整蓝图](https://github.com/Margnus/AI-Note/blob/main/README.md)，本文件负责将其转成可连续执行的小交付。当前是C0/C1，尚未通过整体架构冻结，不批量搬运旧DrawPanel实现。

| D3 生命周期与提交契约 | pending/confirmed、取消、单写者、背压、lease假后端 | 强制调度反例、资源归还、失败状态；明确持久化所有权 | 已有提交/lease/可控调度与关闭/接管模型；已有JVM/Android真实执行器；Apple与生产原生集成待做 |

## D2剩余与D3下一迭代

已生成[候选轨迹](../fixtures/README.md)与hash清单：普通、预测、延迟切层、取消、手指导航。已通过Python格式/顺序/reference投影验证和Kotlin公共状态机→场景命令→内存authority的JSON回放；原生消费未实现，设备和实际延迟为null。这是D2部分成果，不是C0硬件基线完成。

1. 定义真实输入轨迹的schema：单位、pointer/tool、单调时间、历史点、预测点、坐标快照、设备capability。
2. 生成可重复的单笔/急转/长笔/多pointer/CANCEL/切层轨迹；合成轨迹明确标记synthetic，不能伪装真机采集。
3. 已建立S1/S2/S9笔迹子集生成器/hash/分布，补完整混排资产和S9调度反例；不能把笔迹流式消费当全场景性能达标。
4. [旧字段映射](旧格式字段映射.md)已有源码证据，生产静态导入DTO/decoder、合法黄金包与AAR版本对照待做；暂不导入真实个人笔记。
5. [原生采集契约](原生输入采集契约.md)已定义候选字段与测量边界；原生schema/双端实现与实际设备基线待D4。

D3已实现[提交队列候选](adr/0003-submission-ownership-and-retry.md)：满时显式失败、调用方保留完成笔；stop/session close不丢已入队工作；失败/confirmed显式handoff，未知结果重放原patch，确认仍为MEMORY_ONLY。已有[lease假后端与可控调度](adr/0004-resource-lease-and-destruction.md)：预留+resident+retired总charge，borrowed/in-flight为引用子集，close后延迟完成、释放lane及未知结果核对。document/session关闭协调器已完成参考实现，输入停止、提交/资源drain与两步handoff已有可控交错；下一节点验证真实owner执行器和跨线程结果边界；不把LRU驱逐通知当作GPU资源可安全释放的证据。D4完成两端工具链和实际设备验证后才选择原生渲染后端。
