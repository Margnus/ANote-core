### 工具链修复（本轮已完成）

1. `tools/*.py` 共 8 个文件的 `read_text()` 缺少 encoding，中文 Windows 下回落 GBK 抛 `UnicodeDecodeError`，`check_architecture.py` 与 `validate_fixture_catalog.py` 完全无法执行。已全部显式 `encoding='utf-8'`。

### 顺序调整

**调整理由**：C0 基线被跳过，导致最可能推翻架构的事实（渲染后端能力、索引退化、真机延迟）至今零产出，而提交/lease/history 契约已成型。若 PoC 结果为负，部分契约需重做。D5 冻结一个未经测量的架构没有意义。

**调整 1：先闭环分页接线，期间不开新交付。**

评估初稿基于 `de9db39`，当时分页栈在两端零引用；DEV-024D3/D4 已完成接入，该缺口已消除。**剩余工作是收口**：`PreviewNotebook` 与 NCPREVIEW v1 写入路径仍在两端主源码中（Android 3 处、iOS 3 处），`BrushSpec` 在 `PagedPreviewNotebook` 中仍硬编码 `MONOLINE`。建议把“删除单页栈、只保留 v1 只读迁入”作为独立闭环任务，完成前不在分页栈上加新功能。双栈并存违反架构不变量第一条（单一权威），每多存在一轮合并成本越高。

**调整 2：插入不可跳过的测量交付 M-1/M-2/M-3。**

这三项都是 11 号文档 C0/C1 原本要求的产出，不是新增范围：

| 任务 | 内容 | 判定作用 |
|---|---|---|
| M-1 真机基线 | 一台中端 Android + 一台触笔平板；触笔到光子 P95、书写帧稳定、内存 | 性能目标目前无基线，任何实现无法判定达标 |
| M-2 笔刷几何 PoC | 实现 PRESSURE/HIGHLIGHTER 共同几何，两端黄金样本比对 | 决定 Ink API 可否采用、是否自写几何（CN-04 最大变量） |
| M-3 密集页索引 PoC | S2（10,000 笔/1,000,000 点）实测 uniform grid vs R-tree 候选数与更新耗时 | 退化到 K≈N 则 planner 设计需改 |

现状缺口：`BrushSpec` 在 commonMain 的两处构造点均硬编码 `MONOLINE`；压力已采集/校验/持久化但两端渲染只用固定线宽，未映射线宽；无共同几何算法（Android 用 `Path.lineTo`，iOS 用自有 CG 路径）。当前"两端一致"只因都退化为折线，不是已验证的一致性。空间索引、dirty tiles、RenderPlanner、benchmarks 均无实现。

**调整 3：`shared-data` 提到 D6 之前。**

当前"保存"是预览文本格式 + AtomicFile，而 DATA 类 P0（事务、操作日志、checkpoint、断电恢复）需要真实 SQLite 层。继续在预览格式上叠加功能会持续累积迁移成本。
