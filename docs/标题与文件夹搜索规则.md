# SEARCH-01 标题与文件夹搜索规则

## 交付卡

起点Core ff00afe；现行计划允许隔离业务规则。需求：本地离线、中文/英文子串、回收站默认不混入、点击定位。范围为shared-core internal纯元数据规则，复用既有目录/视图快照及校验；不接App、生产索引或正文读取，不引入authority/IO。LIB-09及M-1/C1/正式存储依赖保持。

验收：目录位置与标题元数据必须同空间/同revision且活动noteId集合完全一致；拒绝不完整/坏引用/身份不一致快照。中文及合法Unicode按原字符子串，ASCII英文字母不区分大小写；不做拼音/分词/Unicode归一化或跨平台locale排序。空白查询返回空结果，非空查询保持空格原文，最长120 UTF-16单元，孤立代理项拒绝。笔记标题和目录名分别产出带类型的稳定目标，文件夹先于笔记，同类型按标题/ID确定排序，不通过路径或同名标题定位。

点击定位只接受同空间/版本目标，再查当前元数据得到位置；版本变化必须刷新，不凭旧位置打开另一本。结果只来自活动位置与标题的完整一一对应集，回收站行不得混入标题快照；ID集合不一致必须拒绝，不做交集静默隐藏问题。目标保留kind/space/revision/id，以免同值文件夹和笔记ID混淆。

候选完整扫描限于现有10000目录/100000活动标题准入，结果上限1000；超限整次返回RESULT_CAPACITY，不静默截断，也不称没有结果。无正文、图片或封面读取。不是LIB-09的索引分页或万条性能实现；正式查询需同样匹配语义的索引/分页与稳定版本绑定。

## 接入与实际验收出口

未来唯一元数据事务及列表查询须产生同一revision快照，双端搜索UI需区分空结果、容量拒绝、加载及过期刷新，点击按kind与稳定身份导航。文件夹命中表示打开该文件夹，不自动扩展为其全部子笔记。默认排除回收站不代表已实现单独回收站搜索。实际万条索引/分页、输入取消/旧结果交付、平台搜索与点击定位、耐久重开仍待；隔离规则不代替这些原验收。

## 实际结论

采用为正式查询/导航消费者的匹配与身份校验规则。新增9项共同测试通过，共501项JVM XML零失败，shared本轮执行、canvas复用；[绑定报告](../reports/library-search-rules.json)。可移植性/架构检查通过。无普通App或平台包改动，不重建未变化APK，不宣称万条性能、平台搜索UI或整项需求通过。
