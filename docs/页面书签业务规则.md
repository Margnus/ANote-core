# PAGE-06 页面书签业务规则

## 交付卡

起点Core afc97eb；现行计划允许隔离业务规则。目标：标记/取消书签，重排后按稳定pageId跳转，删页后显式提示目标失效。范围：internal书签元数据计划及原PreviewEdit.SelectPage集成测试，不增文档authority、不改格式/App；只读模式不在本次实现，不以独立boolean状态假装完成输入拦截。PAGE-04/M-1/C1/正式存储与双端验收保持。

验收：书签快照同文档、明确完整、非负匹配元数据revision；拒绝重复/非法pageId/超候选容量。标记须目标页存在，取消允许清理已删页书签；每页最多一个书签，同值计划为无变化。计划绑定文档revision及书签revision，未来事务原子比对应用，失败原件保持。跳转对最新root按pageId查找，不缓存页序；只有仍标记且目标存在才生成原SelectPage请求。重排不使书签失效，删除目标明确MISSING_PAGE，不能跳到占据相同索引的另一页。

## 接入责任

书签是文档关联元数据，不能作为第二内容authority。书签列表可保留已删除目标用于失效提示/清理；恢复相同稳定pageId后可再次定位。ID禁止复用。完整枚举候选最多1000条，非生产heap/页数或UI性能结论。调用期间root及书签列表由同一owner保持稳定；输出只保留单个不可变ID，不持有输入列表。

导航结果不是已跳转回执；原会话仍须校验目标/生命周期/输入pending责任并返回真实结果。生成请求后再删页，原SelectPage必须拒绝，不能取消已接受输入或改选别页。元数据改动不修改笔迹/正文revision，真正持久化须原生产事务及opId协议。跨端书签格式、列表/取消UI、保存重开和只读手指导航/工具保持/模式切换仍待原产品验收。

## 实际结论

采用为未来书签元数据与原页面导航的共享规则。新增6项共同测试通过，包括旧跳转拒绝时活动输入/预留责任保持并可正常完成；共512项JVM XML零失败，shared本轮执行、canvas复用；[绑定报告](../reports/page-bookmark-rules.json)。可移植性/架构检查通过。无平台App改动，不重建未变化APK；未声称书签耐久保存、双端UI或阅读模式完成。
