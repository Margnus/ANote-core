# 预览导入读取结果

DATA-06 / C1第3、4项；Core起点9aae770。现有Android预览已调用同一typed共享reader，但将其拒绝与平台IO、实际写出异常全部转为同一generic消息。修复原入口，不新增格式、authority、队列、资源导入或生产存储。

验收卡：原ContentResolver入口的编码/格式/不支持内容/容量/读取IO及权限拒绝返回明确本地原因，流在成功和失败时关闭；源及已有文件保持。仅源读取阶段映射已知失败，写出异常继续由原执行器标记结果未知，提示先查列表，不能保证失败即未提交或直接引导重试。实际原Store/worker→main回调、拒绝后正常导入并重开需通过。测试用Robolectric resolver注册受控流，不能当作真实系统选择器/ContentProvider/ART验收。

原reader pin/退休规则已收口，生产pin与最终文件退休仍按正式存储门禁。本修复解决的是既有预览的结果表达与流责任；Apple对应入口、权限真实撤销、完整备份/资源事务、跨任务幂等、M-1/C1继续待验。

结果：新增5项主机测试通过，默认25项零失败/零跳过；555共同JVM结果复用，Android构建/lint0错误8警告，可移植性/架构检查通过。原Store串行worker实际读取并经主Looper交付，拒绝后同Store正常导入和重开一致，源/既有字节保持。目录被文件阻塞时写出仍未知，不冒充已回滚。详见[报告](../reports/preview-import-outcomes.json)。null-open分支仅防御实现：Robolectric把null supplier替换为未注册流，不能拿它证明真实null返回已测；权限异常来自受控supplier/read，不是OS撤权。

采用本Android预览结果修复；新APK只构建未安装，旧普通UI证据保持原包绑定。Apple对应入口保持原实现且待验证；不晋升DATA-06完整备份验收。下一步先审查原导入/导出持有的picker/URI权限与owner失败回收责任，只有实际缺陷才修改；生产pin和资源事务仍待原门禁。
