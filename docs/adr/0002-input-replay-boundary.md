# ADR-0002：输入边界与回放参考模型

状态：C1候选，2026-10-14；公开API尚未冻结。

## 决策

平台适配器负责时间单位归一、坐标快照映射、触笔能力及历史点提取；公共核心只接收scene坐标、非负单调微秒、归一压力与pointer标识。JSON解析器只在jvmTest，使用固定kotlinx.serialization 1.9.0；[官方发布说明](https://github.com/Kotlin/kotlinx.serialization/releases/tag/v1.9.0)要求Kotlin2.2，与本原型2.2.21匹配。它不是公共核心的生产依赖或正式文件格式选型。

InputReplaySession是单所有者、单活动触笔的参考状态机：DOWN捕获scene/layer/brush；MOVE按历史顺序追加真实点并替换当前预测预览；UP产生CompletedInput；CANCEL清除未完成轨迹；close终止接收。UP可没有新点，预测专用MOVE可没有真实点，避免复制最后一个点。手指返回导航结果，第二触笔显式拒绝，未来多触笔策略需另行评审。

序号必须严格递增（允许间隔），事件时间不得回退；历史点不得晚于事件时间或早于已有真实点，预测点必须严格位于事件时间之后且递增。拒绝批次不会追加部分点、更新序号或破坏活动轨迹，调用方负责显示失败、重试或显式取消；不得忽略失败并继续宣称轨迹完整。

CompletedInput只含真实StrokeSamples与捕获目标，交给文档authority选取当前baseRevision形成命令；不会捕获DOWN时的场景修订并跨多笔强制复用。暂不自动重试CAS，也不声称任何UP已经磁盘保存。完成输出属于调用方，取消/关闭不得撤销它。内存提交失败时保留输出并由D3明确pending/confirmed处理。

## 资源与性能边界

默认100,000真实点上限，可配置至1,000,000；容量超限显式返回CAPACITY。列表线性追加、UP一次转为防御复制数组，仅为语义参考，仍有重复分配。它没有点arena、分块溢写、worker队列、GPU或线程安全；规模测试通过不代表真机延迟达标。预测列表还需平台与D3的消息/字节预算，不能将真实点上限当成全输入内存上限。

## 证据与后续

公共测试覆盖历史批次、10,000点长笔、取消/重开、切层、关闭、指针冲突、手指导航、序号/时间/预测异常、容量拒绝以及原始列表所有权。JVM回放读取JSON与manifest并核验SHA，5类轨迹经过同一公共状态机、命令prepare及内存authority；逐点核对真实坐标、压力、时间和捕获layer。

这些轨迹全部synthetic。draft只含单位明确的scene坐标、identity快照和零tilt；测试适配器拒绝不支持的快照/笔种/事件，不能当作通用生产解析器。后续补原生转换/能力协议、历史批次JSON与规模样本、旧字段映射、真实设备采集，然后推进D3背压/lease和pending/confirmed契约。C1门禁保持未通过。
