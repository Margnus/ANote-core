# ADR-0023：笔刷解释范围与候选 2 的采用边界

日期：2026-11-22。状态：DEV-036/C1 第 2 项局部决定已采用；正式几何版本和 C1 未冻结。

依据：起始 Core `dc25078433b1a6c60aeabf432026ba56e7d2e05e`，固定 C1 候选仍为 `b299742`。本决定面向 CN-02/03/04、ENG-09、DATA-03、INK-01。当前预览已支持 MONOLINE/HIGHLIGHTER；旧文档“普通 App 仅 MONOLINE”限于各自记录的版本，不能用于描述当前预览或扩展固定 SDK 候选。

## 已观察到的解释差异

| 范围 | 几何与颜色 | 版本责任 |
|---|---|---|
| 当前预览 | 等宽原生 round Path；HIGHLIGHTER 的 alpha 取 `floor(inputAlpha×0.5)`；不按压力改变宽度 | 预览 algorithmVersion 1；文件版本与算法版本分开，预览不是正式格式承诺 |
| `swept-discs-draft-1` oracle | 连续线性圆盘并集；压力半径 `width/2×(0.25+0.75×pressure)`；荧光 alpha 为归一化输入 alpha×0.25 | internal ruleId；借用 BrushSpec 的 1 作为实验入口，不是预览 1 的可互换实现 |
| `BrushGeometryBuilder` 候选 2 | 每点固定 16 边形，非重复位置以法向四边形连接；荧光 alpha 为 `min(inputAlpha,96)`；全部轮廓一次 NON_ZERO 填充 | 独立实验 algorithmVersion 2；不能作为 1 的兼容替代 |

[执行回执](../../reports/c1-brush-profile-decision-20261122/verification.json)保留原实现差分：

- 不透明荧光笔三者的 alpha 分别为 127/255、0.25、96/255；输入 alpha=32 时，预览为 16，候选 2 仍为 32。这不是光栅 AA 或取整差异。
- 宽度 128 单点的探针 `(62,12)` 满足 `62²+12²=3988<64²`，在圆内、在候选 2 多边形外。固定 16 边形的径向缺口 `64×(1-cos(π/16))` 约 1.23 场景单位，乘 4 后约 4.92 目标单位。目标单位还需宿主换算像素；没有进行 AA 或设备像素测量。
- 压力样本 `(0,0,p=0)→(10,0,p=1)`、宽度 8 的 `(5,2.6)` 在连续圆盘扫掠内，却在候选 2 的实际轮廓并集外；`(5,2.7)` 在 oracle 外。候选 2 的法向桥接与连续扫掠不是同一覆盖规则，增加圆盘边数不能单独消除该差异。

## 决定

1. **淘汰候选 2 直接晋升为圆盘扫掠生产实现的路线。** 其固定多边形和法向桥接改变了覆盖，原生坐标量化检查只能限制新增量化误差，不能证明圆盘近似或压感覆盖正确。保留该候选、黄金文件和原生适配作其自身规则的实验参考，不改历史测试或宣称原实现损坏。
2. **采用显式解释范围，淘汰仅改 algorithmVersion 的迁移。** 当前预览、oracle ruleId 与候选 2 分别保留身份。不得把解析 oracle 的 1 当预览支持声明，也不得把已存的 1 改成 2 后重新解释。现有 codec 对 2/未知算法的拒绝保持；SQLite 隔离迁入保留原正文、原算法与原信封，不新增隐式视觉转换。
3. **采用原始真实点及一次整笔覆盖的方向，暂不冻结正式数值规则。** 正式规则必须单独规定尾段、压力函数、同笔 union、对象顺序、透明度与颜色空间。任何与预览颜色/覆盖不同的规则都需新的明确身份和转换决策，不能覆盖已存内容的解释。正式压力体验和目标质量门槛继续等待物理条件。
4. **淘汰用 AA 容差掩盖几何差异的方案。** 几何覆盖、浮点量化、AA 边缘与颜色混合分别核对。本次探针是光栅化前的严格内外差异；既有原生图像结果只证明原报告负载，不晋升为任意缩放/颜色空间一致性。

## 剩余证据及执行顺序

1. 正式覆盖规则明确后，改进共同几何候选以符合该规则；优先处理压力扫掠外切包络和圆盘逼近误差，预算先准入，无法达到精度时显式拒绝，不能改点/加粗/少画。复用现有 oracle、几何结果和平台适配，不建第二 authority 或后台队列。
2. 按同一规则执行单点、急转/折返、跨段接缝、重复点、长笔、任意仿射/大坐标的几何对照；将像素误差阈值与目标 CTM、最大放大倍率绑定。之后才定正式算法编号/迁移。现有算法 2 的实验编号不复用。
3. 同一正式候选再验证双端实际后端的整笔 alpha、颜色与 AA 边缘；各自记录目标格式、色彩空间、CTM、平台版本及失败能力。物理压力体验、M-1 延迟/heap 和 S2/S9 设备索引成本另测。
4. 更新 C1 候选时列出受影响的 SDK/编解码/迁入/渲染消费者并复验。完整六项、最低 iOS 实际运行及物理门槛满足后才冻结 C1、接生产 SQLite。

此次测试在主机 JVM 执行原 common 实现和独立凸轮廓内外查询。没有 App 绘制、普通 OS 输入、Apple/ART 重编译运行、真实设备或生产格式验收。该决定关闭的是“候选 2 能否不经规则变更直接替代”的问题，正式几何交付仍待完成。
