# 第一迭代验收边界

本轮是架构契约原型，不是生产画布性能验收。

| 结论 | 当前能证明 | 不能由此推出 |
|---|---|---|
| 坐标测试 | 在指定范围和500组seed下往返/组合/bbox符合契约 | 所有PDF/设备映射已正确 |
| 样本所有权 | 输入数组后来变更不影响规范数据 | 原生触点不会丢、没有桥接开销 |
| 捕获目标 | 内存提交使用原scene/layer/tool | Android/iOS异步UI已接入 |
| CAS/幂等 | 内存单owner reference拒绝过期patch和冲突ID | 磁盘durability、服务端并发或跨线程安全 |
| 内容修订 | 中间对象更新改变revision并保留旧快照 | tile/索引/GPU完整实现 |
| Frame token | 不匹配revision/generation的结果不得发布 | platform surface已正确释放/重建 |
| 字节LRU | resident计费与重复key淘汰正确、有预算 | 被驱逐资源没有读者/GPU引用或可立即free |
| 依赖校验 | commonMain import和直接project依赖符合当前边界 | 完整AST/反射/传递依赖安全审计 |
| 提交队列 | 单owner FIFO逻辑预算、失败保留、同patch重试与attempt身份 | 实际线程队列背压、全堆/资源硬预算、持久化恢复 |
| 资源lease与释放 | 预留/retire/borrow计费、最后读者与释放确认、UNKNOWN隔离、可控任务顺序 | 原生线程安全、GPU fence、真实析构幂等、实际heap/GPU预算 |
| JVM测试通过 | common代码在JVM实际编译、85项语义/JSON/规模/提交/资源/预览测试通过 | Android/iOS编译和真机性能通过 |

verification.json由Gradle XML和成功任务的input/report SHA-256生成，收集器拒绝新代码对应旧报告。它不是“代码文件存在即通过”，也不是产品发布门禁通过。

后续任何生产实现必须保留这些反例，增加线程/资源/原生/持久化验收；替换reference的数据结构不能改变语义。新旧算法做同样本对比，不能用单测总耗时宣称触笔延迟或百分比提升。

D4预览的独立证据：Android构建+lint见preview-build.json，模拟器运行见android-smoke.json；iOS构建见ios-preview-build.json。上表verification.json仍是共享JVM验证入口，本身不运行平台编译，平台结果不得从其默认false字段反推；以各自匹配输入/产物SHA的报告为准。预览正常文件重开通过不等于断电/损坏恢复或正式durable存储门禁。
