# OBJ05对象顺序独立业务规则

2026-10-30，按现行计划允许的C–F不连接生产范围推进。ObjectOrderRules internal候选只计算顺序计划：FRONT将选中对象稳定移至页内末端，BACK移至页内开头；既有scene顺序决定集合内部顺序，不能按用户点击选择次序逆序。其他页对象的全局槽位保持。当前模型只有规范笔迹，纸张属于PageDescriptor而非scene对象，不允许把页身份当选中对象；这不代表文本/图片对象或套索已实现。

调用者提供原不可变root、documentId、预期revision、pageId、所选ObjectId集合、方向和明确计数额度。错误文档/旧revision/缺页/非法额度/超限/重复或坏Unicode身份/缺失/跨页全拒绝，无变化不出计划。结果复制顺序，不暴露内部可变List；不改root或分配操作身份。计划只在原单一authority版本约定下可重验，不能采用同版本fork，也不是接管许可。计数上界不等于原root/计划字节或完整heap准入，正式owner仍需原额度策略。

实际新增6项共同测试/JVM565项零失败，见[报告](../reports/object-order-rules/report.json)。覆盖多选稳定前后移、其他页槽位、输入/输出无别名、整项拒绝、无变化/旧计划，以及既有PagedPreviewCodec顺序往返。重排fixture只作只读表达验证：SceneSnapshot.reordered不递增revision，原PreviewSaveLedger明确VERSION_CONFLICT，禁止把它直接保存当业务操作。当前Native312项含新增6待真实运行，JVM不代替平台。

采用此纯业务排序规则并限定接入边界；原authority原子排序命令、root/page revision、幂等/undo/redo、对象历史/混排、批注背景选择、双端UI/文件交换与生产保存仍缺。不得以规则计划替代这些原OBJ05条件，也不修改文件版本或生产预览。C1/M-1/DEV041及全部113条验收保持。
