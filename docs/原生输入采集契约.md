# D2原生采集与测量候选契约

状态：C1候选，2026-10-19按现有适配器更新。双端预览已有局部原生采集与合成回归，下列完整采集记录/真机矩阵尚未实现或验收；不沿用早期“平台适配器尚未实现”的绝对描述。本契约供D4 Android/iOS薄适配器与采集工具共同使用，不能由synthetic样本填写真机结果。

## 边界与所有权

平台采集器提取原始真实、历史/coalesced和预测点，保留原始单位/设备能力。归一适配器把它们转为scene坐标、微秒、规范压力与InputBatch。CanvasSession负责活动触笔与预览；文档authority负责已完成笔的提交；renderer负责呈现。原生事件对象与UI可变状态不能被带入worker，必须在回调期间复制需要的标量/缓冲区并记录所有权。

每次真实DOWN记录doc/scene/layer/brush、session generation、工具与pointer，并锁定该笔的目标。MOVE/UP不能通过新的“当前层”改变归属。切页/detach必须显式结束旧输入会话，迟到回调通过generation拒绝；已经交给文档authority的完成输出不随View销毁丢失。

## 采集记录必需字段

| 类别 | 内容 | 校验规则 |
|---|---|---|
| 来源 | schema版本、origin、provider/build版本、设备/OS、屏幕刷新率、输入工具能力 | synthetic与device必须可区分；缺失值为null，禁止猜设备型号/实测值 |
| 时钟 | raw单位、单调clock域/会话origin、raw事件与每个点时间 | 明确统一时钟；整型微秒转换检查溢出；历史点≤事件，预测>事件；墙钟只用于报告时间，不用于轨迹排序 |
| 序列/工具 | sequence、pointerId、phase、tool、generation、真实/历史/预测来源标记 | session内sequence递增；未知tool明确拒绝或导航处理；不能静默把finger当stylus |
| 坐标 | raw坐标/单位、sample对应viewToScene仿射、viewport版本及scene单位 | 在输入边界变换一次；保留快照用于回放核对。旋转/缩放跨历史批次需按sample所属快照处理，不能用最新矩阵映射全部旧点 |
| 能力 | 原生pressure范围/归一方法、tilt/azimuth支持、历史/预测能力、触笔/手指策略 | 缺pressure不等于0压力；提供明确fallback能力策略。旧笔刷算法pressure与原生pressure不能混为一谈 |
| 样本 | x/y、原始与归一pressure、time、可选tilt/azimuth、point来源 | 非有限/非法值返回typed失败；真实点不能因预测更新或重复事件推测被丢弃 |
| 生命周期 | attach/detach/rotate/scene-switch/cancel控制事件 | 同一trace含输入与控制事件、预期接受/拒绝/完成数及失败原因 |
| 校验 | 字节数、SHA、真实/预测/取消点数、完成笔数、截断标记 | 停采或输出失败显式标truncated；已接受内容不可被完整标记掩盖 |

当前JSON 0.1-draft只覆盖synthetic、identity scene快照和零tilt，不具备上表所有字段。升级至原生采集schema前需要版本兼容决定与合法黄金trace；不能仅改版本字符串宣称这些字段已支持。旧持久化笔迹没有真实采样时钟，必须走静态导入模型，不能进入这个采集协议伪造设备事件。

## 当前原adapter实现边界（DEV-040B/D）

Android MotionEvent的真实/历史标量在回调内读取，每次回调捕获原viewport的Double scale/offset；先转Double场景点再交给唯一notebook，派生Path才用Float。原Float逆映射在固定大页/非整数视口下有0.000398681246…额外误差，修复后同样本相对实际SDK标量oracle为0；该结果不是更高精度硬件采样或任意变换的零误差承诺。[原View合成输入报告](../reports/android-input-host-tests.json)4场景验证7点history/terminal顺序、相同时间不同点、压力/微秒/undo-redo及无效/resize迟到取消。其输入是合成MotionEvent直接调用原View，不是系统真实投递或普通包UI。

Apple原View现对DOWN/MOVE/UP立即读取coalesced真实值；数组含主touch副本，不再追加主点两次。无auxiliary时回退main，末点只完成一次；同回调固定坐标快照，非有限/越界坐标和危险Int64时间转换拒绝，预测不进规范样本。[原iOS宿主报告](../reports/ios-host-tests.json)29项含4项合成回调；真实Apple Pencil、估计属性更新和预测纠正仍待验。

这两处采用现有坐标/真实点保留约束，不冻结新的公共API/算法版本；既有笔记不重写。当前预览notebook接口仍逐点接受，不等于原生批量buffer/整个输入管线预算已完成。完整raw clock域、能力/viewport版本记录、跨历史矩阵trace、tilt/azimuth、估计修正、预测纠正、多pointer/平台降级及真实延迟/heap采集仍按上表待做。当前合成报告仅绑定所跑API/SDK，源码不证明runtime实现等价。

## 性能测量链路

分别记录同一真实样本的采集、规范化、入队、预览几何完成、render提交、实际present与durable确认标记；只有能关联同一单调clock域/样本ID的阶段才能计算差值。双端不同clock通过显式校准关联，无法校准则报告不可比较。合成事件间隔、生成器耗时和JVM测试耗时均不能作为实际触笔延迟。

预测点单独统计预览效果及被真实点替换的时机，不得用预测present替代真实sample→present指标。输入序列回放验证保点与目标正确性；真实呈现/物理延迟需平台呈现证据或外部拍摄。保存状态分别呈现pending、memory-only与durable，只有实际磁盘确认可计durable耗时。

采集平台总体内存、在途CPU/GPU资源、队列字节峰值、掉帧及恢复失败。需固定轨迹、构建、算法版本、viewport/屏幕状态、功耗条件、重复次数与原始分布，最终报告P50/P95/P99和峰值；不能直接比较Android/iOS不同口径内存数值。门限沿用蓝图并在C0实测后冻结。

## 设备覆盖与退出条件

先覆盖Android触笔设备、Android手机手指导航、iPad触笔与iPhone导航；分别覆盖实际可用60Hz/高刷新能力、旋转/分屏、前后台、取消、防误触与surface重建。OEM能力是可选port，通用核心不得依赖厂商SDK。具体型号、OS/build、负责人、采集轮次与结果目前未指定，不填写假基线。

D2目前有可重复笔迹子集与字段证据，原生schema/采集尚未验证。D3先实现模型级pending/confirmed、字节背压和lease；D4再接双端采集器，补真实trace与平台构建；D5结合设备结果冻结正式输入/数据/资源契约。
